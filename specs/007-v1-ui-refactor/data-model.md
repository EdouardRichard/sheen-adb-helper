# Phase 1 Data Model: v1.0 全功能 UI 重构

**Date**: 2026-07-26
**Spec**: [spec.md](./spec.md)

All runtime entities below are ephemeral unless explicitly backed by existing settings. Every device-derived entity carries or is owned by a `SessionIdentity`; results from a different Session are rejected before UI state mutation.

## 1. Shared application state

### `SessionIdentity`

| Field | Type | Rules |
|---|---|---|
| `sessionId` | opaque string | Generated by the existing Session manager; never inferred from endpoint text |
| `connected` | boolean | False invalidates all device-owned state |
| `deviceLabel` | presentation-safe string? | Must not be persisted in test evidence with real identifiers |

### `MainDestination`

Ordered enum:

1. `CONNECTION`
2. `FILES`
3. `APPLICATIONS`
4. `PROCESSES`
5. `SHELL`
6. `LOGCAT`

### `PageHostState`

| Field | Type | Rules |
|---|---|---|
| `current` | `MainDestination` | Single source for page content and selected navigation item |
| `pending` | `MainDestination?` | Latest accepted transition request only |
| `transition` | `IDLE / FADING_OUT / FADING_IN` | Business page-entry effects run once after acceptance |
| `foreground` | boolean | False stops/cancels lifecycle-bound work |
| `overlay` | `RootOverlay?` | Pairing and global confirmations take back priority |
| `navigationLock` | `NavigationLock?` | Blocks bottom navigation and horizontal gestures |

### `NavigationLock`

| Field | Type | Rules |
|---|---|---|
| `owner` | page + task ID | Exactly one active blocker exposed to App |
| `kind` | file upload/download, APK extract/install, Logcat save, screenshot save, screen-recording save/export | Shell and Logcat collection are excluded; Logcat save is included |
| `ioStarted` | boolean | Lock exists only after actual device transfer or host output writing starts; picker browsing/cancel is false and unlocked |
| `phase` | transferring/writing, verifying, cancelling, cleaning | Navigation remains blocked in every owned non-terminal phase |
| `progress` | bounded progress? | May be indeterminate |
| `cancelAvailable` | boolean | User-visible cancel entry required |
| `businessResult` | complete/partial/failed/cancelled/unknown? | Kept separate from resource cleanup certainty |
| `cleanupConfirmed` | boolean | Navigation may resume only at a safe terminal result; retained committed partial outputs are not cleanup failures |

State transitions:

```text
UNLOCKED
  -> LOCKED_ACTIVE (only when actual transfer/write begins)
LOCKED_ACTIVE
  -> {COMPLETE_SUCCESS_SAFE | PARTIAL_SUCCESS_SAFE | FAILED_SAFE | CANCELLING}
CANCELLING
  -> CLEANING
  -> {CANCELLED_SAFE | FAILED_UNKNOWN}
COMPLETE_SUCCESS_SAFE / PARTIAL_SUCCESS_SAFE / FAILED_SAFE / CANCELLED_SAFE
  -> UNLOCKED
FAILED_UNKNOWN
  -> remains locked until ownership/cleanup is resolved or Session is definitively closed
```

Opening, browsing, or cancelling a system picker never creates this entity. Copying text, viewing existing results, the Shell child stream, and Logcat collection also never create it.

### `DeliveryIoState`

Shared Feature-to-App description for a transfer or persistent output:

| Field | Type | Rules |
|---|---|---|
| `taskId/sessionId` | opaque IDs | Stable across language changes; stale Session results are rejected |
| `kind` | same set as `NavigationLock.kind` | Owned by the corresponding Feature |
| `phase` | awaiting-selection/preparing/transferring/writing/verifying/cancelling/cleaning/terminal | `awaiting-selection` and picker cancellation are not blocking |
| `result` | complete/partial/failed/cancelled/unknown? | Business delivery result |
| `resourceState` | owned/releasing/released/uncertain | Only owned/releasing/uncertain after I/O starts can hold the lock |

`:core:adb` and `:core:data` report their own phases/results; the owning Feature reduces them into `DeliveryIoState`; `:app` derives `NavigationLock` without interpreting storage or ADB errors.

## 2. Files

### `FilePageState`

| Field | Type | Rules |
|---|---|---|
| `sessionId` | string? | Change clears all fields below |
| `directory` | absolute remote path | Current breadcrumb target |
| `breadcrumbs` | list of label/path | Each item independently actionable |
| `sourceEntries` | immutable list | Latest accepted Session snapshot |
| `visibleEntries` | derived list | Directory-first, group time descending, stable |
| `scrollAnchor` | key + offset | Same Session only |
| `status` | disconnected/loading/content/empty/error/unsupported | Must represent real state |
| `transfer` | `FileTransferTask?` | At most one due exclusive lease |

### `FileEntry`

Identity is Session ID + absolute path + observed snapshot generation.

Relevant fields: display name, absolute path, kind, enterable/selectable, size, modification epoch, link resolution, source order.

Sort key:

```text
(group: directory=0/file=1,
 timeKnown: known=0/unknown=1,
 modifiedEpochSeconds: descending when known,
 sourceOrder: ascending)
```

### `FileTransferTask`

Contains task ID, Session ID, direction, source/target, conflict state, byte progress, lease, staging handle, cleanup state, and structured result.

Terminal states distinguish success, user cancel, timeout, permission denied, conflict cancelled, unsupported provider/device, disconnected, failed-safe, and outcome-unknown.

## 3. Applications

### `ApplicationPageState`

| Field | Type | Rules |
|---|---|---|
| `sessionId` | string? | Change clears snapshot/query/scroll/task |
| `applications` | immutable snapshot | Loaded explicitly; not per keystroke |
| `draftQuery` | string | User input |
| `appliedQuery` | string | Updated only by search button |
| `visibleApplications` | derived list | Matches display name or package name |
| `scrollAnchor` | key + offset | Same Session only |
| `status` | disconnected/loading/content/empty/error/degraded | Includes unknown classification |
| `confirmation` | `ApplicationConfirmation?` | One pending destructive confirmation |
| `task` | `ApplicationTask?` | Exclusive extraction/install task or short mutation |

### `ManagedApplication`

| Field | Type | Rules |
|---|---|---|
| `identity` | Session + user + package | Immutable target identity |
| `packageName` | string | First row |
| `displayName` | string | Second row; safe fallback if unavailable |
| `classification` | ordinary/system/unknown | Unknown uses system restrictions |
| `enabledState` | enabled/disabled/unknown | Determines enable/disable icon only for ordinary apps |
| `version` | optional metadata | Display/state only |
| `apkComponents` | unknown or list | Loaded when extraction/preflight needs it |

Allowed direct actions:

| Classification | Actions |
|---|---|
| ordinary | extract, enable/disable, force-stop, uninstall |
| system | extract only |
| unknown | extract only |

The install flow may target an already installed system/unknown package only after package preflight and the dedicated force-install confirmations.

### `ApkComponent`

Fields: remote path handle, role `BASE` or `SPLIT`, safe output name, byte size if known, digest/verification result if available. Raw remote paths remain core-owned and are not logged.

### `ApkComponentDelivery`

| Field | Type | Rules |
|---|---|---|
| `componentId` | opaque component identity | Corresponds to exactly one base/split component without exposing raw remote path |
| `role/displayName` | base/split + safe name | User-visible result identity |
| `phase` | pending/transferring/verifying/committing/terminal | At most one component owns the active stream/staging target |
| `result` | committed/failed/cancelled/not-attempted | `committed` requires successful write and verification |
| `bytes` | bounded progress | Never inferred as success from bytes alone |
| `error` | structured failure? | Localized only by presentation |

### `ApkExtractionTask`

```text
SELECT_DESTINATION
  -> DISCOVER_COMPONENTS
  -> PREPARE_OUTPUT
  -> TRANSFERRING(component)
  -> VERIFYING(component)
  -> COMMITTING(component)
  -> RECORD_COMPONENT_RESULT
  -> {NEXT_COMPONENT | COMPLETE_SUCCESS | PARTIAL_SUCCESS | FAILED_NONE_COMMITTED}
```

For split apps, the destination is one new independent directory. Every component uses the existing single-file staging/verification/commit safety where supported, but the component set is not atomic. A committed component remains in the user-selected directory if another component fails; only the current uncommitted temporary, stream, and lease enter cleanup. Remaining components continue unless cancellation, disconnect, Session change, or lost ownership makes continuation impossible.

Overall result rules:

- `COMPLETE_SUCCESS`: every expected component is committed;
- `PARTIAL_SUCCESS`: at least one component is committed and at least one is failed, cancelled, or not attempted;
- `FAILED_NONE_COMMITTED`: no component committed;
- `CANCELLED`: cancellation occurred before any component committed;
- `OUTCOME_UNKNOWN`: component/result ownership cannot be established safely.

Every terminal result exposes the full `ApkComponentDelivery` list. No state claims cross-file atomic commit, automatic rollback, or deletion of already committed files.

### `ApkInstallCandidate`

| Field | Type | Rules |
|---|---|---|
| `sourceHandle` | SAF reference | User selected, never raw filesystem path |
| `displayName` | string | Must end in `.apk` for initial acceptance |
| `isStandalone` | yes/no/unknown | Reject known split/incomplete set; unknown requires core preflight |
| `packageIdentity` | package/version/signature relation | Derived without exposing signing material |
| `installedRelation` | absent/same-signature/different-signature/unknown | Drives confirmation flow |
| `targetClassification` | ordinary/system/unknown/not-installed | System policy is never bypassed |

### `ApkInstallTask`

State transitions:

```text
SELECTED
  -> VALIDATING
  -> READY
READY + installed absent
  -> INSTALLING
READY + same signature
  -> AWAIT_FORCE_CONFIRMATION
  -> INSTALLING_REPLACE_OR_DOWNGRADE
READY + different/unknown signature
  -> AWAIT_FORCE_CONFIRMATION
  -> AWAIT_UNINSTALL_CONFIRMATION
  -> UNINSTALLING_OLD
  -> INSTALLING_NEW
```

Terminal states:

- `SUCCESS`;
- `CANCELLED_BEFORE_MUTATION`;
- `REJECTED_INPUT`;
- `UNINSTALL_FAILED`;
- `INSTALL_FAILED_OLD_RETAINED`;
- `INSTALL_FAILED_OLD_REMOVED_NO_ROLLBACK`;
- `POLICY_BLOCKED_SYSTEM_PACKAGE`;
- `TIMEOUT`;
- `DISCONNECTED`;
- `OUTCOME_UNKNOWN`.

The task never reports rollback. Private data preservation is claimed only for a platform-confirmed same-signature replace; mismatch uninstall explicitly deletes current-user private data.

### `ApplicationConfirmation`

Nonce-bound union:

- enable/disable target and impact;
- force-stop target and impact;
- uninstall target and private-data deletion;
- force install replace/downgrade;
- signature-mismatch uninstall then install;
- system-package policy warning.

Each confirmation binds Session ID, user ID, package identity, task/candidate fingerprint, and a one-use nonce.

## 4. Processes

### `ProcessPageState`

| Field | Type | Rules |
|---|---|---|
| `sessionId` | string? | Change resets |
| `generation` | long | Each accepted snapshot advances |
| `entries` | immutable list | Current snapshot |
| `query` | string | Immediate local process-name filter |
| `visibleEntries` | derived list | Case-insensitive process-name match |
| `scrollAnchor` | key + offset | Same Session only |
| `visible/foreground` | booleans | Both true to run cadence |
| `refreshState` | stopped/waiting/loading | Never more than one active request |
| `confirmation` | scope selection? | Single process or whole application |

### `ProcessEntry`

Identity: Session ID + PID + process start/observation identity + snapshot generation. Fields include process name, optional package/application association, CPU percentage or unknown, PSS bytes or unknown.

### Refresh transitions

```text
HIDDEN/STOPPED
  -> VISIBLE_WAITING
  -> REFRESHING
  -> VISIBLE_WAITING (next delay measured after completion)
```

Any leave/background/disconnect/Session change cancels the active wait/request and transitions to `STOPPED`. Stale completions fail identity checks.

## 5. Interactive Shell

### `ShellPageState`

| Field | Type | Rules |
|---|---|---|
| `sessionId` | string? | Change clears all terminal context |
| `streamGeneration` | long | New value for every child stream |
| `streamState` | closed/opening/ready/remote-active/closing/error | Old generation events are discarded |
| `records` | bounded deque | Same Session memory only |
| `filter` | string | Immediate local derived view |
| `draft` | editable command | Never sent per keystroke |
| `history` | bounded commands | Same Session memory only |
| `historyCursor` | optional index | Local up/down before submission |
| `modifier` | none/ctrl/alt/ctrl+alt | One-shot; clears after next input or lifecycle reset |
| `autoScroll` | boolean | Presentation only |
| `pendingRiskConfirmation` | nonce + complete command? | No bytes sent before confirmation |

### `TerminalRecord`

Fields: record ID, stream generation, kind (local command, stdout, stderr, system separator/status), timestamp/order, bounded text. Filter changes only visible records.

### `TerminalInput`

Core-owned union:

- text/bytes;
- newline/submit;
- Escape;
- Tab;
- ArrowUp;
- ArrowDown;
- one-shot modified input.

The Feature requests semantic inputs; only `:core:adb` encodes control bytes/escape sequences.

### Stream transitions

```text
CLOSED -> OPENING -> READY
READY -> REMOTE_ACTIVE -> READY
READY/REMOTE_ACTIVE -> CLOSING -> CLOSED
any -> ERROR -> CLOSING -> CLOSED
```

Leave/background closes the child stream and clears draft, remote-active state, pending confirmation, and modifier. Records/history remain only if the main Session remains the same. Return appends a separator and opens a new stream generation.

## 6. Logcat

### `LogcatPageState`

| Field | Type | Rules |
|---|---|---|
| `sessionId` | string? | Change clears |
| `windowId` | opaque ID? | New on every explicit Start |
| `collectionState` | never-started/starting/collecting/stopped/limit/error | Never auto-started |
| `rawWindow` | bounded ordered records | Maximum 10 MiB or 10 minutes |
| `textFilter` | string | Local |
| `levelFilter` | all/debug/info/error | English labels in all locales |
| `visibleRecords` | derived list | Text AND severity predicate: all=all; debug=Debug+; info=Info+; error=Error/Fatal |
| `exportTask` | `DeliveryIoState?` | Uses immutable complete-window snapshot; lock starts only after the output target returns and writing begins |

### `LogRecord`

Fields: window ID, sequence, parsed severity (verbose/debug/info/warn/error/fatal/unknown), raw sanitized display text, byte cost. The exact collected raw record is used for export; filtering never mutates it.

`:core:adb` owns parsing to the normalized Fatal severity. `:feature:logcat` owns the local predicates: Fatal matches `all`, `debug`, `info`, and `error`; no fifth Fatal button exists.

### Collection transitions

```text
NEVER_STARTED
  -> STARTING
  -> COLLECTING
COLLECTING
  -> STOPPED_BY_LEAVE
  -> STOPPED_BY_USER
  -> LIMIT_TIME
  -> LIMIT_BYTES
  -> ERROR
```

Explicit Start from any retained state first clears the old window and creates a new `windowId`. Delete clears the entire raw window but does not silently restart collection. Export takes an immutable snapshot at button time so later lines cannot change the file being written.

## 7. Pairing and connection overlays

### `RootOverlay`

Union:

- `PairingOverlay`;
- operation confirmation;
- long-task back confirmation.

Only one root overlay is interactive at a time. Outside tap is accepted only when the active overlay declares itself dismissible.

### `PairingOverlay`

| Field | Type | Rules |
|---|---|---|
| `attemptId` | opaque ID | New for every QR/code/local attempt |
| `origin` | discovered device/local pairing | Presentation and lifecycle |
| `mode` | QR/code/local-code | Switch cancels prior temporary observation |
| `phase` | QR-ready/scanning/port-found/input-ready/submitting/success/error/timeout/cancelled | Visible in app |
| `deadline` | monotonic time | Code scan is at most 30 seconds |
| `endpointHandle` | core-owned reference? | Not persisted or logged |
| `code` | mutable six-char secret | Cleared on every terminal/dismiss transition |
| `submitEnabled` | derived boolean | Exactly six ASCII digits and input-ready |

Transitions:

```text
QR_READY
  -> SCANNING (user switches to code)
SCANNING
  -> INPUT_READY (one valid NSD pairing service)
  -> TIMEOUT
INPUT_READY
  -> SUBMITTING (explicit Pair only)
  -> CANCELLED
SUBMITTING
  -> SUCCESS / ERROR / TIMEOUT
```

Outside tap, close, back, disconnect, Session change, or App background cancels temporary discovery/wait and clears all sensitive fields.

### `ConnectionErrorPresentation`

Fields: visible error ID, semantic safe-message key plus typed arguments, and optional sanitized technical code. Compose resolves the current language; dismiss removes this presentation only. Endpoint inputs, discovery snapshot, pairing state not owned by the error, and active Session are unchanged.

### `OverviewQuickActionState`

Owned by `:feature:overview` for the connected Connection destination.

| Field | Type | Rules |
|---|---|---|
| `kind` | screenshot/screen-recording/reboot | Existing ADR 0008 capability |
| `sessionId/artifactId` | opaque IDs | Old Session/artifact results are rejected |
| `phase` | capturing/recording/awaiting-destination/writing/terminal | `awaiting-destination` is picker-visible and unlocked |
| `delivery` | `DeliveryIoState?` | Screenshot/recording persistent write maps to a lock only in writing/verification/cleanup |
| `result` | semantic result + technical code? | Presentation resolves text in `:feature:overview` |

`:app` launches the existing SAF picker and returns the project-owned target; it does not own capture/export business transitions. Screenshot/recording capture before persistent export remains governed by the existing quick-action lifecycle and is not reclassified as an output-write navigation lock.

## 8. UI presentation primitives

### `DesignTokenSet`

Contains local color roles, spacing in 4 dp increments, 44 dp minimum touch target, page margins, component gaps, radii, typography roles, and terminal/code styles. No URL or remote asset may be represented.

### `UiRecordKey`

Every `LazyColumn`/`LazyRow` record uses a stable key containing Session/window/snapshot identity as appropriate. A visible label alone is never used as identity.

## 9. Localization presentation state

### `LanguagePreferenceState`

| Field | Owner | Rules |
|---|---|---|
| `persistedValue` | `:core:data` | Exactly `zh-CN` or `en-US`; missing/corrupt uses existing `zh-CN` fallback |
| `flow` | `:core:data` → `:app` | Collected once at the root Compose host |
| `uiLanguage` | `:app`/`:core:ui` | Pure presentation mapping; never part of Session, ViewModel or operation identity |

`:feature:settings` requests preference changes but is not another state source. Android application-locale APIs, configuration recreation, and a second locale DataStore are outside this model.

### `LocalizedTextRef`

| Field | Type | Rules |
|---|---|---|
| `owner` | shared/app/feature identifier | Page-specific semantics stay in the owning Feature; shared chrome/common states stay in `:core:ui` |
| `semanticKey` | typed key | Chinese and English catalogs contain identical required key sets |
| `arguments` | typed list/map | Placeholder names/types are identical across languages |
| `rawArguments` | typed markers | Path, package/process name, PID, command, Shell/Logcat text, version and technical code remain verbatim |

ViewModels expose semantic state/error codes plus typed arguments, not frozen localized prose and not `AdbError.userMessage/nextStep`. Compose resolves `LocalizedTextRef` from the current `UiLanguage` during recomposition. Missing English for any v1.0 target key is a contract failure rather than an accepted fallback.

Language changes may alter only rendered text, accessibility semantics and locale-aware presentation formatting. They must not change Session ID, page/scroll identity, ViewModel instance, task ID/phase, navigation lock, Shell stream generation, Logcat window/collection, pairing attempt, picker request, draft input, or device/SAF request counts.

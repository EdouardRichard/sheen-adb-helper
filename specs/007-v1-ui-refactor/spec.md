## Clarifications

### Session 2026-07-26

- Q: Shell 页采用持续交互式终端、一次性命令模式还是混合模式？ → A: 采用持续交互式终端；输入内容和特殊键发送到当前终端子流，离开终端页时关闭该子流，但不影响主 ADB Session。
- Q: Logcat 下载保存全部采集日志还是当前过滤结果？ → A: 保存本次采集窗口中的全部日志；文本和级别过滤只影响屏幕显示。
- Q: 多 APK 应用提取为独立目录、ZIP 还是每次选择？ → A: 在用户选择的位置创建独立目录，输出 base APK 和全部 split APK。
- Q: v1.0 五个重构页面与连接修复采用何种语言覆盖？ → A: 全部支持简体中文和 English；日志级别 `all/debug/info/error` 始终保持英文。
- Q: 文件传输、APK 提取/安装等长任务进行中是否允许切页？ → A: 长任务过程中不允许切页；任务结束或取消后恢复导航，应用进入后台时取消长任务。
- Q: 触屏 Ctrl/Alt 采用一次性修饰、持续锁定、按住组合还是立即发送？ → A: 采用一次性修饰；点击后高亮，只修饰下一次字符或特殊键输入，发送后自动解除。
- Q: 卸载普通应用时删除还是保留应用私有数据？ → A: 完整卸载并删除该用户下的应用私有数据；每次操作前明确确认。
- Q: 安装 APK 遇到已安装同包名应用时，强制安装如何处理覆盖、降级和签名不一致？ → A: 提示用户选择强制安装；同签名允许覆盖或降级，签名不一致时再次提示先完整卸载旧应用，再安装新应用。
- Q: 持续交互式 Shell 如何兼顾普通输入与高风险命令的执行前确认？ → A: 普通命令先在主控端输入区组成，提交时统一发送；高风险命令发送前确认，特殊键继续实时发送。
- Q: 存在待提交命令时，特殊键作用于本地输入还是远端终端？ → A: 命令提交前特殊键作用于本地编辑与历史；提交后远端程序运行期间才实时发送到终端子流。
- Q: 离开 Logcat 页后，已采集日志是否保留？ → A: 离页停止采集但保留当前有界快照；返回后可查看或下载，重新开始时清空旧窗口并建立新采集。
- Q: 应用页如何保留既有强制停止能力？ → A: 普通应用增加直接强制停止图标按钮，右侧顺序为下载、禁用/启用、强制停止、卸载；系统应用仍只显示下载。
- Q: 配对端口单次扫描多长时间后超时？ → A: 30 秒；超时后显示未发现配对端口并提供重试，每次重试建立新的 30 秒扫描。
- Q: 六位配对码输入后如何提交配对？ → A: 输入完整六位数字后启用明确的“配对”按钮，只有用户点击该按钮才提交。
- Q: 长任务运行期间触发系统返回应如何处理？ → A: 先显示确认；只有用户选择取消任务并离开，且任务完成取消与清理后才执行返回。
- Q: 应用提取结果是否要求支持多 APK 恢复安装？ → A: 提取与安装是独立功能；v1.0 安装仅接受单个 APK，不支持多 APK 组成安装，也不承诺提取结果可直接装回。
- Q: 同一设备 Session 内切页后是否保留页面状态？ → A: 保留各页路径、查询、滚动位置和最近快照；返回时先恢复并按页面规则刷新，断开或 Session 切换时清空。
- Q: Shell 离页关闭终端子流后是否保留本地记录与命令历史？ → A: 同一 Session 内仅在内存保留；返回时建立新子流并插入会话分隔，断开或 Session 切换时全部清空。
- Q: 普通状态下，主页面的系统返回如何处理？ → A: 任意主页面直接退出应用，不在六个主页面之间返回；浮层、确认框和长任务返回确认优先处理。
- Q: 强制安装遇到同包名系统应用时如何处理？ → A: 与普通应用相同；签名不一致时二次确认后尝试卸载再安装，设备策略不允许时明确失败。
- Q: `Fatal` 日志应归入哪个现有级别？ → A: `error` 显示 Error 与 Fatal；`all`、`debug` 和 `info` 依其最低严重度语义也包含 Fatal。
- Q: SAF 多文件提取中任一文件失败时如何提交结果？ → A: 允许部分成功并保留已验证写入的文件；逐项报告每个文件的成功或失败及整体“部分成功”终态，不承诺原子提交或自动回滚。
- Q: 哪些操作属于阻止切页的“输出文件写入”？ → A: 覆盖文件下载、APK 提取、Logcat 保存、截屏保存和既有录屏保存/导出；从实际传输或写入开始锁页，文件选择器浏览与取消阶段不锁页。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 通过统一导航浏览工具页 (Priority: P1)

已连接用户可通过底部导航或左右滑动在“连接、文件、应用、进程、终端、日志”之间切换。页面内容按目标设计稿显示，切换采用淡出淡入；连接页之前和日志页之后不存在可继续滑动的页面。同一 Session 内返回页面时恢复该页路径、查询、滚动位置和最近非实时快照，不因切页重复发起全量请求；断开或 Session 切换时清空旧页面状态。

**Why this priority**: v1.0 的核心价值是形成一致、可预测的完整工具界面，且不破坏连接状态。

**Independent Test**: 建立一个活动连接，分别用底部按钮和滑动遍历六页，核对顺序、选中态、动画、首尾边界、返回行为和 Session 连续性。

**Acceptance Scenarios**:

1. **Given** 当前已连接且位于任一页面，**When** 用户点击底部导航项，**Then** 切换到对应页面并以淡出淡入完成过渡，底部选中态与可见页面一致。
2. **Given** 当前已连接且位于相邻页面之一，**When** 用户完成一次有效水平滑动，**Then** 只切换一个相邻页面，页面顺序固定为“连接、文件、应用、进程、终端、日志”。
3. **Given** 用户位于连接页或日志页，**When** 用户分别向序列外侧滑动，**Then** 页面保持不变，不出现空白页、循环跳转或错误选中态。
4. **Given** 切页动画正在进行，**When** 用户再次点击导航或滑动，**Then** 最终只落在一个明确目标页，不叠加页面、不创建重复操作。
5. **Given** 当前没有活动连接，**When** 用户尝试进入需要被控端的页面，**Then** 保持既有连接门槛并提示先连接，不创建空会话。
6. **Given** 用户在设置中切换简体中文或 English，**When** 任一 v1.0 目标页或新增连接修复界面可见，**Then** 页面标签、提示、状态、错误、确认和可访问性说明立即使用所选语言，且不重启或取消当前业务状态；Logcat 四个级别标签保持英文。
7. **Given** 文件上传/下载、APK 提取/安装、Logcat 保存、截屏保存或既有录屏保存/导出已经开始实际传输或写入，**When** 用户点击其他底部导航项或执行水平切页手势，**Then** 保持当前页面并明确提示先完成或取消任务；任务终态后导航自动恢复。仅浏览或取消文件选择器、复制文本、查看结果、Logcat 采集和 Shell 会话不得触发该导航锁。
8. **Given** 长任务正在运行，**When** 用户触发系统返回键或返回手势，**Then** 拦截返回并显示“继续任务”与“取消任务并离开”的确认；默认留在当前页，只有用户明确选择后者且任务完成取消与清理后才执行返回。
9. **Given** 用户在同一 Session 内离开并返回文件、应用或进程页，**When** 页面重新可见，**Then** 先恢复该页路径或查询、滚动位置和最近快照；进程页恢复可见刷新，其他页面只在既有触发条件或数据失效时刷新，不得仅因返回而重复全量读取。
10. **Given** 设备断开或活动 Session 切换，**When** 任一页面重新显示，**Then** 清空旧 Session 的页面状态和快照，不得恢复旧设备的路径、查询结果、滚动位置或数据。
11. **Given** 当前没有需要优先关闭的浮层、确认框或活动长任务，**When** 用户在任意主页面触发系统返回键或返回手势，**Then** 直接退出应用并执行既有后台生命周期，不得切换到上一访问页、左侧相邻页或连接页。

### User Story 2 - 浏览并传输被控端文件 (Priority: P1)

用户在文件页查看当前路径和远端条目。用户只能点击文件夹行尾进入图标进入目录，只能点击文件行尾下载图标下载该文件，并可用右下角上传入口从主控端选择文件上传到当前目录。

**Why this priority**: 文件浏览和双向传输是核心设备操作，且现有能力与新交互模式差异明确。

**Independent Test**: 在包含多级目录、不同时间文件、同名冲突和空目录的被控端路径中，验证路径跳转、排序、行点击边界、上传、下载、取消和失败恢复。

**Acceptance Scenarios**:

1. **Given** 当前目录具有多级路径，**When** 用户点击任一可见路径段，**Then** 加载该路径对应目录，并更新当前路径和列表。
2. **Given** 当前目录同时包含文件夹和文件，**When** 列表显示，**Then** 所有文件夹始终位于所有文件之前，文件夹组和文件组各自按修改时间倒序排列；时间未知条目位于所属组末尾且排序稳定。
3. **Given** 用户点击文件夹行尾进入图标，**When** 目录可访问，**Then** 进入该文件夹；点击该行其他区域不选择、不进入、不触发传输。
4. **Given** 用户点击文件行尾下载图标，**When** 用户选择主控端输出目录并确认，**Then** 下载该文件并显示有界进度和明确终态；点击该行其他区域不响应。
5. **Given** 用户点击右下角上传图标，**When** 从主控端选择一个可读文件，**Then** 上传到当前被控端目录，并保留既有冲突选择、取消、超时、失败与清理行为。
6. **Given** 目录为空、不可读、设备断开或路径在请求期间失效，**When** 请求结束，**Then** 页面分别显示空状态或可操作错误，不展示上一目录内容为当前结果。

### User Story 3 - 搜索、提取、管理和安装应用 (Priority: P1)

用户可按应用名或包名搜索被控端应用。每个应用格先显示包名、再显示应用名；普通应用依次提供 APK 提取、禁用/启用、强制停止和卸载图标按钮，系统应用只显示 APK 提取。用户还可从右下角入口选择主控端 APK 安装到被控端。

**Why this priority**: 应用页既要严格适配设计稿，又存在 APK 提取、安装和卸载三项当前能力缺口。

**Independent Test**: 使用普通启用应用、普通禁用应用、系统应用、名称未知应用和无效 APK，验证搜索、按钮显隐与右移、提取、禁用/启用、卸载、强制停止和安装结果。

**Acceptance Scenarios**:

1. **Given** 应用列表已加载，**When** 用户按名称或包名输入并点击搜索图标，**Then** 仅显示匹配项；简体中文输入框提示文本为“请输入应用名或包名。”，English 使用语义等价的英文提示。
2. **Given** 任一应用格显示，**When** 用户查看文本顺序，**Then** 第一行是包名，第二行是应用名；名称不可读取时显示明确未知状态，不把包名重复伪装为应用名。
3. **Given** 条目是普通应用，**When** 用户查看行尾操作，**Then** 图标按钮按“下载、禁用/启用、强制停止、卸载”从左到右排列并整体右对齐；当前已禁用应用在禁用按钮原位置提供重新启用语义。
4. **Given** 条目是系统应用，**When** 用户查看行尾操作，**Then** 禁用/启用、强制停止与卸载按钮均不显示且不占位，下载按钮向右补位；系统应用不得通过隐藏区域或误触发执行这些受限操作。
5. **Given** 用户点击下载图标，**When** 被控端应用存在一个或多个可提取 APK，**Then** 系统让用户选择主控端输出位置；单 APK 应用交付该 APK，多 APK 应用在该位置创建独立目录并尝试输出 base APK 与全部 split APK。全部文件写入并验证后显示成功；任一文件失败时保留已验证文件，逐项显示成功与失败，并将整体结果标记为部分成功而非完整成功。
6. **Given** 用户点击普通应用的禁用或卸载图标，**When** 风险确认显示，**Then** 卸载确认明确说明将删除该用户下的应用及应用私有数据，但不宣称删除共享存储中的外部文件；只有用户确认后才对当前 Session 和目标应用执行一次操作，并区分成功、拒绝、不支持、超时和结果未知。
7. **Given** 用户点击右下角安装入口，**When** 从主控端选择一个有效的单 APK 文件，**Then** 对未安装包执行正常安装；遇到已安装同包名应用时先让用户选择强制安装或取消，并显示进度与终态。入口使用贴近“上传到设备/安装包”的图标，不得使用加号。
8. **Given** 用户对已安装同包名应用选择强制安装，**When** 新旧包签名一致，**Then** 允许覆盖升级或降级并保留既有应用私有数据；未选择强制安装时不替换现有应用。
9. **Given** 用户选择强制安装但新旧包签名不一致，**When** 风险确认显示，**Then** 明确说明必须先完整卸载旧应用及其应用私有数据，且新包后续安装失败时无法自动恢复；只有再次确认后才按“卸载旧应用 → 安装新应用”的顺序继续。
10. **Given** 条目是普通应用，**When** 用户点击行尾强制停止图标，**Then** 在发送前明确提示目标和影响；用户确认后执行既有强制停止流程，取消、返回或关闭时不发送请求。
11. **Given** 强制安装目标与已安装系统应用同包名且签名不一致，**When** 用户完成二次风险确认，**Then** 尝试按“卸载旧应用 → 安装新应用”执行；若设备策略不允许完整卸载、系统基础包仍阻止安装或任一阶段失败，必须停止并显示真实终态，不得使用 Root、扩大权限或伪装成功。

### User Story 4 - 搜索并结束进程 (Priority: P1)

用户在进程页通过单一搜索框即时过滤进程，并查看每个进程的名称、CPU 和内存占用。页面可见且已连接时，数据每 5 秒更新；点击行尾结束图标后，用户每次都选择结束单个进程或按应用结束。

**Why this priority**: 进程状态具有实时性和风险，刷新节奏与结束范围必须明确且可控。

**Independent Test**: 使用可关联应用、不可关联应用、PID 复用、刷新超时和 Session 切换数据，验证即时过滤、5 秒刷新、无重叠请求和两种结束范围。

**Acceptance Scenarios**:

1. **Given** 进程列表已加载，**When** 用户输入文本，**Then** 列表立即按进程名过滤，无需搜索按钮；清空输入后恢复当前快照。
2. **Given** 进程页保持可见且 Session 未变化，**When** 每个 5 秒刷新点到达，**Then** 更新当前 Session 的 CPU 与内存数据；上一刷新未结束时不得启动重叠刷新。
3. **Given** 页面进入后台、切到其他工具页、断开或切换 Session，**When** 下一个刷新点到达，**Then** 不再刷新旧页面或旧 Session，旧结果不得覆盖新 Session。
4. **Given** 用户点击某一进程行尾结束图标，**When** 该进程可关联到应用，**Then** 每次都先让用户选择“结束单个进程”或“按应用结束”；未选择或取消时不发送请求。
5. **Given** 进程无法可靠关联应用，**When** 用户打开结束选择，**Then** 仅提供单进程选项并说明整应用选项不可用。
6. **Given** 结束请求发出后 PID 被复用、设备断开或结果不可验证，**When** 操作结束，**Then** 不把请求已发送或条目暂时消失直接宣称为成功。

### User Story 5 - 使用被控端 Shell 终端 (Priority: P1)

用户在终端页查看高对比度持续交互式终端面板，通过主控端输入法在本地输入区组成普通命令，提交时再发送到当前终端子流并在被控端执行；高风险命令必须在发送前确认。顶部工具栏提供清空、过滤和自动滚动开关；面板底部提供 Esc、Tab、Ctrl、Alt、上、下键和用于请求输入焦点及弹出输入法的回车图标按钮。命令提交前，特殊键作用于本地编辑与命令历史；命令提交后远端程序运行期间，特殊键才实时作用于终端子流。离开终端页时终端子流关闭，但同一 Session 的可见记录与命令历史仅在内存中保留；返回时建立新子流并显示会话分隔，主 ADB Session 保持不变。

**Why this priority**: Shell 是高价值高级工具，UI 重构不能削弱既有风险控制、取消和输出边界。

**Independent Test**: 在正常命令、长输出、高风险命令、超时、取消和断开场景中，验证命令执行、过滤、自动滚动、特殊键、输入法入口和终端状态。

**Acceptance Scenarios**:

1. **Given** Shell 页已连接且输入区域获得焦点，**When** 用户输入普通字符，**Then** 字符先组成主控端待提交命令且不逐键发送；用户提交后，完整命令只进入当前被控端 Session 的持续交互式终端子流，终端面板按先后顺序显示命令与结果。
2. **Given** 用户点击清空，**When** 当前没有需要确认的不可中断终态，**Then** 清除主控端可见终端记录，不向被控端发送清除设备数据的命令。
3. **Given** 用户启用过滤并输入文本，**When** 文本变化，**Then** 立即过滤可见终端记录；关闭过滤恢复当前有界记录且不重新执行命令。
4. **Given** 自动滚动开启，**When** 新输出到达，**Then** 视图跟随最新内容；用户关闭自动滚动后，新输出不得强制改变其阅读位置。
5. **Given** 普通命令尚未提交，**When** 用户点击 Esc、Tab、Ctrl、Alt、上或下键，**Then** 对应意图只作用于主控端本地编辑、一次性修饰状态或命令历史，不得发送到远端终端子流。
6. **Given** 命令已经提交且远端程序正在运行，**When** 用户点击 Esc、Tab、上或下键，**Then** 立即将对应输入意图发送到当前终端子流；不支持时显示明确降级，不把按钮当作普通文本写入。
7. **Given** 用户点击 Ctrl 或 Alt，**When** 按钮进入高亮的一次性修饰状态，**Then** 在提交前只修饰下一次本地字符或特殊键输入，在远端程序运行期间只修饰下一次实时输入，并在该输入处理、用户取消、离页、断开或 Session 切换后自动解除。
8. **Given** 输入法未显示，**When** 用户点击底部最右侧回车图标按钮，**Then** 终端输入区域获得焦点并请求显示主控端输入法；该点击本身不得偷偷执行空命令。
9. **Given** 待提交命令被识别为高风险，**When** 用户提交，**Then** 在任何命令内容或换行进入终端子流前显示风险确认；用户取消、返回或关闭时不发送该命令。
10. **Given** 命令运行超时、用户取消或 Session 变化，**When** 流程结束，**Then** 保留有限超时、取消、结果分类和资源清理，不允许旧输出进入新 Session。
11. **Given** 持续交互式终端正在运行，**When** 用户切换到其他工具页或应用进入后台且原 Session 仍有效，**Then** 立即关闭当前终端子流并清理待提交命令、实时输入阶段与修饰状态，但在内存中保留可见记录和命令历史，不结束主 ADB Session。
12. **Given** 用户在同一 Session 内返回 Shell 页，**When** 页面重新可见，**Then** 显示保留的记录与历史并建立新的终端子流，在新旧子流内容之间显示明确会话分隔；不得恢复已关闭的旧子流。断开或 Session 切换时必须清空全部终端上下文。

### User Story 6 - 按需查看并保存 Logcat (Priority: P1)

当前 Session 尚无保留窗口时，用户进入日志页先看到开始入口，只有点击后才采集当前被控端日志。顶部功能栏提供即时过滤、`all/debug/info/error` 四档日志级别、清空和下载；离开日志页立即停止采集但保留当前有界快照，返回后仍可查看或下载，明确重新开始时才清空旧窗口并建立新采集。

**Why this priority**: Logcat 含敏感且高频数据，必须由用户主动开始并严格限制生命周期和资源占用。

**Independent Test**: 使用混合级别日志、快速过滤、长时间输出、清空、保存、离页、断开和 Session 切换场景验证采集边界与显示结果。

**Acceptance Scenarios**:

1. **Given** 当前 Session 尚无保留的 Logcat 采集窗口，**When** 用户进入日志页但未点击开始，**Then** 不读取被控端 Logcat，只显示开始入口和空状态。
2. **Given** 用户点击开始且当前已连接，**When** 采集建立，**Then** 只采集当前 Session，并显示正在采集与停止能力；重复点击不得创建第二个采集。
3. **Given** 用户输入过滤文本，**When** 文本发生变化，**Then** 立即过滤当前内存窗口中的可见日志，不重新启动采集。
4. **Given** 用户选择日志级别，**When** 选择 `all`、`debug`、`info` 或 `error`，**Then** 分别显示全部、Debug 及更高、Info 及更高、Error 与 Fatal 日志；Warning 日志包含在 `all/debug/info` 中，Fatal 日志包含在全部四档中，二者均不新增独立按钮。
5. **Given** 用户点击删除图标，**When** 当前日志窗口被清空，**Then** 页面立即为空，后续新日志仍可继续显示；不得清除被控端系统的其他持久数据。
6. **Given** 用户点击下载图标，**When** 选择主控端保存位置，**Then** 将本次采集窗口中的全部日志保存为文件，不受当前文本或级别过滤影响，并在写入可验证后显示完成；取消或失败不得宣称成功。
7. **Given** 用户切换到其他页面或应用进入后台且原 Session 仍有效，**When** 页面不再满足采集条件，**Then** 立即停止当前采集并释放采集资源，但保留当前有界快照；返回日志页后只显示该静态快照及开始入口，不得自动恢复采集。
8. **Given** 采集达到既有 10 分钟或 10 MiB 任一边界，**When** 边界先到，**Then** 停止采集并明确说明原因，不进行无界缓存或后台续采。
9. **Given** 日志页存在已停止的保留快照，**When** 用户明确点击重新开始，**Then** 清空旧窗口并为当前 Session 建立新的有界采集；断开或 Session 切换时必须清除旧 Session 快照。

### User Story 7 - 修复连接、配对和截屏反馈 (Priority: P1)

未连接用户可以关闭错误卡。点击扫描结果中的未配对设备时，页面上方弹出二维码配对浮层；用户可切换为配对码模式，应用主动扫描配对端口并在发现后提供输入。用户执行本机配对时同样获得明确提示和主动端口扫描。截屏完成后只显示保存按钮。

**Why this priority**: 这些缺陷直接阻断连接或导致误导性反馈，必须与全页面 UI 重构一起消除。

**Independent Test**: 分别使用已配对连接服务、未配对服务、本机配对、端口未出现/过期、错误状态和截屏成功场景，验证浮层、关闭、扫描和反馈。

**Acceptance Scenarios**:

1. **Given** 连接页显示错误卡，**When** 用户点击右上角关闭按钮，**Then** 错误卡消失且不改变当前输入、扫描结果或 Session；新错误仍可再次显示。
2. **Given** 用户点击扫描结果中的已配对连接服务，**When** 目标仍有效，**Then** 进入既有连接流程，不错误弹出配对浮层。
3. **Given** 用户点击扫描结果中的未配对设备，**When** 目标需要配对，**Then** 在当前应用页面上方显示二维码配对浮层，而不是把二维码嵌入连接页内容流。
4. **Given** 二维码浮层显示，**When** 用户点击背景透明的“切换配对码配对”文字按钮，**Then** 切换到配对码模式并开始最长 30 秒的单次端口扫描；简体中文立即显示“正在扫描配对端口”，English 显示语义等价文本，发现有效端口后显示六位数字配对码输入框和“配对”按钮。
5. **Given** 二维码或配对码浮层显示，**When** 用户点击非配对相关的浮层外区域、返回或关闭，**Then** 关闭浮层、停止本次临时扫描/等待并清除二维码、配对码和临时端点。
6. **Given** 用户发起本机配对，**When** 配对窗口开始，**Then** 弹出明确操作提示并开始最长 30 秒的单次本机配对端口扫描；扫描期间简体中文显示“正在扫描配对端口”，English 显示语义等价文本，发现后允许输入系统显示的六位数字配对码并显示“配对”按钮。
7. **Given** 配对端口在 30 秒内未出现，**When** 单次扫描超时，**Then** 显示“未发现配对端口”的等价结果并提供重试；只有用户点击重试后才能建立新的 30 秒扫描，不得在后台自动续扫。
8. **Given** 配对端口过期、配对被拒绝、用户取消或 Session 变化，**When** 流程结束，**Then** 显示可操作非成功结果并清理临时状态，不伪装为已配对或已连接。
9. **Given** 配对端口已发现，**When** 用户输入不足六位、含非数字或只触发输入法完成动作，**Then** “配对”按钮保持禁用且不得发送配对请求；只有六位数字完整且用户点击已启用的“配对”按钮后才提交一次。
8. **Given** 被控端截屏已完成且结果可保存，**When** 连接页显示操作结果，**Then** 不显示“录屏”或额外成功提示文本，只显示现有保存按钮；保存、取消和清理流程保持不变。

### Edge Cases

- 同一目录中修改时间相同或未知时，文件夹优先规则不变，同组排序必须稳定，刷新时不得无故跳动。
- 文件名、应用名、包名、进程名、Shell 输出和 Logcat 含超长文本、控制字符、双向文本或不可解码字节时，界面必须安全截断/替换并允许查看，不得破坏布局或作为命令再次执行。
- 文件上传/下载、APK 提取/安装、Logcat 保存、截屏保存或既有录屏保存/导出已经开始实际传输或写入时，底部导航和水平切页手势不得离开当前页；重复导航不得复制任务，应用进入后台、断开或 Session 切换时取消并清理长任务。文件选择器仍在浏览或被取消、只复制文本、只查看结果、Logcat 正在采集或 Shell 会话活动时，不得仅因此启用导航锁。
- 长任务返回确认被取消、关闭或选择继续时不得发送取消请求或离开当前页；选择取消任务并离开后，若取消超时、结果未知或清理未完成，必须留在当前页显示对应结果，不得让任务无归属地继续。
- 主控端文件选择被取消、来源不可读、目标不可写、空间不足或同名冲突时，保持原文件不变并显示可恢复结果。
- 多 APK 应用的目标独立目录已存在时，必须沿用用户选择且默认取消的冲突策略；分包缺失、应用在提取期间更新或卸载、安装包损坏/不兼容或任一文件写入失败时，不得报告完整成功。已经写入并验证的文件必须保留，未完成或验证失败的文件不得标记成功，并逐项显示文件名、结果与失败原因；该流程不承诺跨文件原子提交或自动回滚。
- v1.0 安装入口只接受一个 APK 文件，不接受 APK 目录、多选文件、`.apks`、`.xapk` 或其他多 APK 容器；用户选择 split APK、缺少必要 split 的 base APK 或其他不可独立安装文件时，必须显示不支持或安装失败，不得自动关联同目录文件。
- 应用是否为系统应用无法可靠判断时，按更安全的系统应用限制处理：不显示禁用/启用、强制停止与卸载。
- 普通应用卸载确认被取消、返回或关闭时不得发送请求或删除任何数据；卸载成功只表示该用户下的应用和应用私有数据已按系统语义移除，不得宣称共享存储中的外部文件也已删除。
- 强制安装的首次确认被取消时保持现有应用不变；签名不一致的二次确认被取消时不得卸载旧应用。若用户确认后旧应用已卸载但新包安装失败，必须报告不可自动恢复的失败，不得伪装回滚成功或恢复已删除数据。
- 同包名目标是系统应用时，列表页仍不得显示卸载按钮；只有签名不一致的强制安装二次确认流程可以尝试卸载。设备只移除当前用户安装状态、保留系统基础包、拒绝卸载或仍因签名冲突拒绝安装时，必须报告对应失败或结果未知，不得宣称系统应用已完整移除。
- 进程刷新跨越 PID 复用、整应用进程集合变化或 Session 切换时，只能操作确认时绑定的身份集合；旧快照不得授权新进程。
- Ctrl/Alt 已进入一次性修饰状态但下一输入为空、被拒绝、取消或超时时，不得把修饰键单独发送；必须解除高亮并保持页面可操作。输入法拒绝显示或设备 Shell 不支持交互键时显示明确降级。
- 高风险命令确认显示期间，待提交命令不得部分发送、提前发送换行或被特殊键绕过；取消确认后返回输入区并原样保留待提交文本，不得自动执行。
- 本地待提交命令存在时，任何特殊键不得提前流入远端；远端程序运行期间的实时特殊键不得反向修改已经提交的本地命令历史。
- Shell 离页后保留的记录与命令历史必须保持静态且仅驻留内存；返回页建立新子流时不得把旧子流标记为仍在运行，也不得让方向键跨 Session 读取旧设备命令。
- 用户在 Logcat 过滤后清空时，清除本次采集窗口中的全部日志而不只是可见子集；保存时同样以操作发生时的完整采集窗口创建快照，后续筛选条件或新日志不得改变该保存任务。
- Logcat 离页或应用进入后台后保留的快照必须保持静态，不得继续追加；重新开始会替换旧窗口，断开或 Session 切换必须清除旧 Session 快照，不得混入新 Session。
- 配对浮层关闭、页面切换、应用退到后台或连接成功后，二维码、配对码和临时端口不得保留在页面、历史、日志或持久化存储中。
- 配对端口单次扫描达到 30 秒仍未发现目标时必须停止；超时页面不得暗中续扫，连续点击重试不得创建重叠扫描。
- 配对码为空、不足六位、超过六位或包含非数字时不得启用“配对”按钮；快速重复点击、输入法完成动作或输入变化不得创建重复配对请求。
- 用户在文件传输、应用操作、进程确认、持续交互式 Shell、Logcat 采集或配对进行中切换语言时，只更新可见文案和可访问性说明，不得重建、重复发送、取消或改变操作归属。
- 水平滑动与列表垂直滚动、终端/日志横向查看、系统返回手势冲突时，只有明确完成的页面切换手势改变页面，内容操作不得被误判为切页。
- 系统返回必须先交由当前浮层、确认框或长任务返回确认处理；这些临时层均不存在时才直接退出应用。退出不得被记录为主页面访问历史，也不得触发中间页面业务请求。
- 任何页面的旧异步结果到达新 Session 后都必须丢弃；不得把旧设备的文件、应用、进程、Shell、Logcat 或配对状态显示为当前设备数据。
- 同一 Session 的页面状态恢复不得把已失效的加载、错误、确认或操作中状态重新激活；数据因操作完成或设备通知而失效时必须按页面规则刷新，不得继续把旧快照伪装为当前结果。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 以“连接、文件、应用、进程、终端、日志”为唯一移动端主页面顺序，并保持底部导航和可见页面选中态一致。
- **FR-002**: 已连接且没有活动长任务时，用户 MUST 能通过底部导航或一次有效水平滑动切换到一个目标/相邻页面；连接页外侧和日志页外侧 MUST NOT 再切换。
- **FR-003**: 页面切换 MUST 使用淡出淡入效果；快速连续导航 MUST 收敛到一个明确页面且不得重复触发页面业务操作。
- **FR-004**: 未连接时，所有需要被控端的页面 MUST 保持不可用并引导用户先连接。
- **FR-005**: 文件、应用、进程、Shell 和 Logcat 页 MUST 以各自 `code.html` 的结构、层级、主要尺寸、控件位置和图标语义为 UI 基准，以 `screen.png` 进行视觉核对。
- **FR-006**: 当设计稿遗漏本规格明确要求或既有已授权能力时，系统 MUST 补充该能力；补充内容不得移除、替换或重排设计稿中已存在且被本规格确认的核心控件。
- **FR-007**: 页面 MUST 覆盖加载、内容、空、错误、取消、断开、能力不支持和结果未知状态，不得用静态设计样例伪装真实设备数据。
- **FR-008**: UI 运行时 MUST 使用本地资源，不得因设计还原请求远程字体、样式、图标或其他 Web 资源。
- **FR-009**: 文件页 MUST 在顶部栏下显示当前路径，并允许用户点击任一路径段切换到对应目录。
- **FR-010**: 文件列表 MUST 将所有文件夹排在所有文件之前，并在文件夹组和文件组内分别按修改时间倒序排序；未知时间条目置于所属组末尾且排序稳定。
- **FR-011**: 文件夹只能通过行尾进入图标进入，文件只能通过行尾下载图标发起下载；两类条目的其他行区域 MUST NOT 响应点击。
- **FR-012**: 文件页右下角 MUST 提供上传图标入口，允许用户从主控端选择一个文件上传到当前被控端目录。
- **FR-013**: 文件上传与下载 MUST 保留冲突确认、进度、取消、有限超时、Session 归属、结构化错误和确定性清理。
- **FR-014**: 应用页顶部栏下 MUST 显示搜索框，简体中文提示文本为“请输入应用名或包名。”，English 使用语义等价的英文提示；搜索图标按钮位于输入框右侧。
- **FR-015**: 应用搜索 MUST 同时匹配应用名和包名，并在用户点击搜索图标后更新结果；空查询 MUST 显示当前完整列表。
- **FR-016**: 每个应用格 MUST 第一行显示包名、第二行显示应用名；普通应用右侧图标按钮 MUST 按“下载、禁用/启用、强制停止、卸载”顺序排列并整体右对齐。
- **FR-017**: 系统应用 MUST 只显示下载按钮；禁用/启用、强制停止和卸载按钮 MUST 隐藏且不保留空占位，剩余下载按钮 MUST 右移补位；无法可靠分类时 MUST 采用系统应用限制。FR-020 的签名不一致强制安装流程是唯一允许尝试卸载同包名系统应用的例外，不得由列表隐藏区域直接触发。
- **FR-018**: 普通应用的下载按钮 MUST 提取当前安装 APK；单 APK 应用 MUST 交付该 APK，多 APK 应用 MUST 在用户选择的位置创建独立目录并尝试输出 base APK 与全部 split APK。只有全部文件写入并验证后才能报告完整成功；任一文件失败时 MUST 保留已验证写入的文件，逐项报告每个文件的成功或失败，并将整体结果标记为部分成功。多文件提取 MUST NOT 承诺跨文件原子提交或自动回滚。
- **FR-019**: 普通应用的禁用、启用、强制停止和卸载操作 MUST 继续可用，并在发送前显示目标和影响确认；卸载 MUST 明确提示将删除该用户下的应用与应用私有数据且不保留数据，取消时 MUST NOT 发送请求；强制停止 MUST 使用 FR-016 定义的直接图标按钮，不得藏入补充入口。
- **FR-020**: 应用页右下角 MUST 提供从主控端选择一个 APK 文件并安装到当前被控端的入口；图标 MUST 表达上传/安装到设备语义且 MUST NOT 使用加号。v1.0 MUST NOT 接受 APK 目录、多选 APK、`.apks`、`.xapk` 或其他多 APK 组成，也 MUST NOT 将提取结果解释为可直接恢复安装。遇到已安装同包名应用时 MUST 提供“强制安装”或取消选择：同签名强制安装允许在设备策略允许时覆盖升级或降级并保留应用私有数据；签名不一致时 MUST 再次确认完整卸载旧应用及其私有数据后再安装新包。该规则同样适用于同包名系统应用，但不得使用 Root、扩大权限或绕过系统策略；系统应用无法完整卸载或底层系统包继续造成签名冲突时 MUST 明确失败。
- **FR-021**: 应用提取、安装和卸载 MUST 显示有界进度与成功、部分成功、失败、取消、超时、拒绝、不支持或结果未知，并绑定发起时 Session；多文件提取的部分成功 MUST 同时提供逐文件结果。签名不一致的强制安装 MUST 明确显示“卸载旧应用”和“安装新应用”两个阶段；旧应用已卸载但新包安装失败时 MUST 报告不可自动恢复且 MUST NOT 伪装回滚。系统应用卸载只影响当前用户或保留底层系统包时 MUST 如实表达，不得报告为完整卸载。
- **FR-022**: 进程页顶部栏下 MUST 提供不含搜索按钮的单一搜索框，并随输入即时按进程名过滤当前快照。
- **FR-023**: 每个进程格 MUST 显示进程名及其 CPU、内存占用；不可读取字段 MUST 显示未知，不得以零值或旧值伪装。
- **FR-024**: 进程页可见且已连接时 MUST 每 5 秒刷新一次；刷新不得重叠，离页、后台、断开或 Session 切换后 MUST 停止。
- **FR-025**: 每个进程格右侧 MUST 提供结束进程图标；每次点击 MUST 让用户选择结束单个进程或按应用结束，可用范围取决于可靠应用关联。
- **FR-026**: 结束进程 MUST 保留确认时身份、取消、有限超时、结构化结果、PID 复用防护和 Session 切换防护。
- **FR-027**: Shell 页顶部栏下 MUST 依次提供清空、过滤和自动滚动开关，并在其下显示占据主要空间的高对比度终端面板。
- **FR-028**: Shell MUST 为当前被控端 Session 建立单一持续交互式终端子流。普通字符 MUST 先在主控端输入区组成待提交命令且不得逐键发送；提交时统一发送完整命令。高风险命令 MUST 在任何命令内容或换行进入终端子流前确认，并保留取消、有限超时和结果未知表达。同一 Session 返回 Shell 页时 MUST 建立新子流且 MUST NOT 恢复已关闭的旧子流。
- **FR-029**: Shell 过滤 MUST 随过滤文本即时更新当前有界记录且不得重新执行命令；清空 MUST 只清除主控端可见记录。
- **FR-030**: 自动滚动开启时 Shell MUST 跟随新输出，关闭时 MUST 保留用户阅读位置。
- **FR-031**: 终端面板底部 MUST 按设计稿提供 Esc、Tab、Ctrl、Alt、方向上、方向下按钮。普通命令提交前，所有特殊键 MUST 只作用于主控端本地编辑、命令历史或一次性修饰状态且 MUST NOT 发送到远端；命令提交后远端程序运行期间，Esc、Tab 和方向键 MUST 实时发送到当前终端子流，Ctrl/Alt MUST 只修饰下一次实时输入。Ctrl/Alt 在下一输入处理、用户取消、离页、断开或 Session 切换后 MUST 自动解除，任何键名不得作为普通文本或独立命令发送。
- **FR-032**: 底部键栏最右侧 MUST 提供回车图标按钮；点击 MUST 聚焦终端输入并请求弹出主控端输入法，点击本身 MUST NOT 执行空命令。
- **FR-033**: 当前 Session 尚无保留采集窗口时，Logcat 页 MUST 保持未采集状态并提供开始按钮；只有用户明确点击开始后才能读取当前被控端日志。
- **FR-034**: Logcat 页顶部功能栏 MUST 依次提供即时过滤输入框、`all`、`debug`、`info`、`error` 级别按钮、删除图标和下载图标；不得使用设计稿中的中文级别文案。
- **FR-035**: Logcat 文本过滤 MUST 随输入立即作用于当前内存窗口，不得重新启动采集。
- **FR-036**: Logcat 级别 MUST 使用最低严重度语义：`all` 显示全部，`debug` 显示 Debug 及更高，`info` 显示 Info 及更高，`error` 显示 Error 与 Fatal；Fatal MUST 包含在全部四档中且不得新增独立按钮。
- **FR-037**: Logcat 删除图标 MUST 清空本次主控端采集窗口中的全部日志；下载图标 MUST 将操作时的完整采集窗口快照保存到用户选择的主控端位置，文本和级别过滤 MUST 只影响屏幕显示。实际文件写入开始后 MUST 遵循 FR-057 的导航锁。
- **FR-038**: Logcat 切页或进入后台时 MUST 停止采集并释放采集资源；原 Session 仍有效时 MUST 保留当前有界快照供返回后查看或下载，但 MUST NOT 自动续采。用户明确重新开始时 MUST 清空旧窗口并建立新采集；断开或 Session 切换时 MUST 清除旧 Session 快照。
- **FR-039**: Logcat 单次采集 MUST 保留既有 10 分钟或 10 MiB 先到即止边界，并在到达边界时显示明确终态。
- **FR-040**: 连接页错误卡右上角 MUST 提供关闭按钮，关闭只清除当前可见错误，不改变连接输入、发现结果或 Session。
- **FR-041**: 点击已配对连接服务 MUST 进入既有连接流程；点击未配对发现设备 MUST 在应用页面上方打开二维码配对浮层。
- **FR-042**: 二维码浮层下方 MUST 提供背景透明的“切换配对码配对”文字按钮。
- **FR-043**: 切换到配对码模式后 MUST 主动开始最长 30 秒的单次配对端口扫描；简体中文 MUST 显示精确文本“正在扫描配对端口”，English MUST 显示语义等价文本；发现有效端口后 MUST 显示仅接受六位数字的配对码输入框和明确的“配对”按钮。
- **FR-044**: 点击配对浮层外区域、返回或关闭 MUST 关闭二维码/配对码浮层、停止临时扫描或等待并清除敏感临时状态。
- **FR-045**: 本机配对 MUST 弹出明确操作提示并主动开始最长 30 秒的单次本机配对端口扫描；扫描、发现、输入、可提交、提交中、成功、失败、取消和超时状态 MUST 在应用内可见。
- **FR-046**: 二维码、配对码和本机配对 MUST 保留单一活动尝试、取消、Session 归属和敏感值清理，不得写入持久化记录或日志。端口扫描在 30 秒超时后 MUST 停止、显示未发现结果并提供重试；重试 MUST 由用户明确触发并建立新的 30 秒扫描，且 MUST NOT 与旧扫描重叠。配对码只有在恰为六位数字时才能启用“配对”按钮，且 MUST 只在用户点击该按钮后提交一次；输入法动作和输入变化 MUST NOT 自动提交。
- **FR-047**: 截屏成功后连接页 MUST 移除任何误写为录屏或额外成功提示的文本，只显示既有保存按钮；只有用户保存完成后才能报告交付成功，实际文件写入开始后 MUST 遵循 FR-057 的导航锁。
- **FR-048**: 文件传输、应用操作、进程结束、Shell、Logcat 和配对结果 MUST 绑定发起时的唯一活动 Session；旧 Session 结果 MUST NOT 更新新 Session。
- **FR-049**: 原始 ADB 命令、协议流、Socket、配对材料和异常适配 MUST 保持在既有 ADB 边界内；页面及业务功能不得直接拼接原始命令或访问连接通道。
- **FR-050**: 所有长任务、轮询和采集 MUST 支持取消、有限超时、结构化错误与确定性资源清理；Shell 终端子流 MUST 在离开终端页或应用进入后台时关闭且不得断开仍有效的主 ADB Session。原 Session 仍有效时，Shell MUST 仅在内存保留可见记录和命令历史，清除待提交命令、实时输入阶段与修饰状态；返回页建立新子流时 MUST 插入明确会话分隔。断开或 Session 切换时 MUST 清空全部终端上下文。Logcat 采集 MUST 按 FR-038 在离页时停止。
- **FR-051**: 过滤、排序和刷新 MUST 基于当前内存窗口或当前快照，不得为每次输入触发新的被控端全量请求。
- **FR-052**: 本版本 MUST 保持纯本地，不得新增账号、后端、广告、统计/遥测、支付、Root、无障碍自动化或业务云请求。
- **FR-053**: 本版本 MUST NOT 扩大 Manifest 权限；主控端文件选择与输出必须继续由用户明确选择。
- **FR-054**: 设计稿中的真实样例端点、包名、文件名、Shell 和 Logcat 内容 MUST 仅作为设计占位，不得进入产品默认数据、测试记录或诊断记录。
- **FR-055**: 用户可见构建版号 MUST 更新为 `v1.0`，设置/关于或菜单中的版本展示 MUST 与实际构建一致，不得沿用设计稿占位值或旧版号。
- **FR-056**: 文件、应用、进程、Shell、Logcat 及本版本新增连接修复的全部用户可见标签、提示、状态、错误、确认和可访问性说明 MUST 支持简体中文与 English；切换语言 MUST 只更新呈现且不得改变业务状态，Logcat 的 `all/debug/info/error` 标签在两种语言下均保持英文。
- **FR-057**: 文件上传/下载、APK 提取/安装，以及向主控端写入文件的 Logcat 保存、截屏保存和既有录屏保存/导出 MUST 作为阻止切页的长任务。导航锁 MUST 从实际传输或写入开始时生效；文件选择器浏览或取消阶段 MUST NOT 启用导航锁。运行期间底部导航和水平切页 MUST 保持当前页面并提供取消入口，任务完成、部分成功、失败或取消后恢复导航，应用进入后台、断开或 Session 切换时 MUST 取消并清理。长任务期间系统返回 MUST 先显示“继续任务”与“取消任务并离开”的确认；只有用户明确选择后者且取消与清理完成后才能执行返回，取消超时、结果未知或清理未完成时 MUST 留在当前页。复制文本、仅查看结果、Shell 终端子流和 Logcat 采集不属于此导航锁；后两者仍按各自离页停止规则处理。
- **FR-058**: 同一活动 Session 内，文件、应用和进程页 MUST 在内存中保留路径或查询、滚动位置和最近非实时快照，返回时先恢复这些状态；不得仅因切页返回而重复发起文件或应用全量读取，进程页按 FR-024 恢复可见刷新。断开或 Session 切换时 MUST 清空旧 Session 页面状态。Shell 与 Logcat MUST 分别遵循 FR-028、FR-038 和 FR-050 的专属生命周期。
- **FR-059**: 当前不存在需要优先关闭的浮层、确认框或活动长任务时，任意主页面上的系统返回 MUST 直接退出应用并执行既有后台生命周期，MUST NOT 在六个主页面之间返回。配对浮层按 FR-044 关闭，操作确认框按对应取消语义关闭，长任务按 FR-057 显示返回确认。

### Scope Boundaries

- v1.0 覆盖文件、应用、进程、Shell、Logcat 五页 UI 重构、全局滑动/淡入淡出导航，以及用户明确列出的连接页缺陷修复；已完成的菜单页和已基本完成的连接页只做必要修复与一致性收口，不进行无关重做。
- v1.0 将既有简体中文/English 语言设置扩展到五个重构页面及新增连接修复；技术数据、命令、路径、包名、进程名和用户/设备原始内容不得被翻译。
- UI 冲突优先级为：本规格及用户明确补充说明 → 目标页面 `code.html` 的结构、组件、尺寸、图标语义和状态 → `DESIGN.md` 的通用设计语义与未覆盖设计令牌 → `screen.png` 视觉核对。设计稿占位数据不得覆盖真实产品状态。
- 本阶段不引入多设备并行控制、后台常驻采集、批量应用操作、多 APK 组成安装、递归文件同步、文件编辑、图形化命令生成器或新的诊断历史。
- 版本内保留既有强制停止、重新启用、传输冲突处理、高风险 Shell 确认、Logcat 有界采集和连接/配对安全语义；UI 不得以“设计稿未展示”为由删除它们。
- 若实现 APK 提取/安装/卸载或交互式 Shell 键输入需要新的协议、权限、依赖或架构例外，必须在 Plan 阶段明确设计并按工程治理处理；本规格本身不授权扩大权限或放宽 ADB 边界。

### Key Entities

- **工具页位置**: 当前六页顺序中的页面、底部选中态、滑动目标和过渡状态；主页面不维护供系统返回使用的页面访问历史。
- **页面状态快照**: 绑定当前 Session 的页面路径或查询、滚动位置、最近非实时数据、失效状态和恢复时机；不包含按专属生命周期管理的 Shell 终端子流或 Logcat 活动采集。
- **导航锁**: 当前阻止切页的长任务、所属页面、Session、实际传输/写入开始状态、可取消状态、系统返回确认状态和解除原因。
- **远端文件条目**: 当前 Session 下的绝对路径、名称、类型、修改时间、大小、权限、可进入/可下载状态。
- **应用条目**: 包名、应用名、系统应用分类、启用状态、APK 组成和可用操作。
- **应用交付任务**: APK 提取、单 APK 安装或卸载的目标 Session、来源/输出选择、提取时的单 APK 文件或多 APK 独立目录、base/split 预期集合及逐文件写入/验证结果、安装时的单一 APK 来源、目标应用系统分类、签名一致性、覆盖/降级选择、卸载时应用私有数据删除语义、系统基础包保留状态、分阶段进度和整体结果。
- **进程快照**: 当前 Session 和采样时间对应的进程身份、进程名、CPU、内存及可靠应用关联。

## Assumptions

- 页面滑动只在存在活动连接且目标页面可用时生效；未连接状态仍停留在连接页。
- 既有本地语言偏好继续作为唯一语言来源；v1.0 把覆盖范围扩展到五个重构页面和新增连接修复，默认语言与持久化行为保持不变。
- 应用搜索保留用户明确要求的搜索图标触发方式；进程、Shell 和 Logcat 的本地过滤随输入即时生效。
- 现有普通应用“重新启用”和“强制停止”是需要适配而非删除的旧功能；禁用按钮按状态切换为重新启用语义，强制停止作为直接图标按钮加入普通应用右侧操作组，四个按钮固定按“下载、禁用/启用、强制停止、卸载”排列。
- 系统应用仍允许在设备能力和策略允许时提取 APK，但不显示禁用、强制停止或卸载按钮。签名不一致的同包名强制安装经二次确认后可尝试卸载再安装；该例外不得绕过系统策略，失败或部分移除必须如实报告。
- 普通应用卸载采用不保留应用私有数据的完整卸载语义；共享存储中的外部文件不属于卸载成功声明范围。
- 强制安装同包名应用时，同签名允许在设备策略允许时覆盖或降级并保留应用私有数据；签名不一致必须二次确认先尝试完整卸载旧应用及其私有数据，再安装新包，且不承诺失败回滚。该规则也适用于系统应用，但系统策略拒绝或底层系统包保留时必须停止并如实报告。
- “下载应用”表示尝试提取当前已安装 APK 组成；分包应用在用户选择的位置创建独立目录并尝试写入 base APK 与全部 split APK，不使用 ZIP 归档。多文件写入允许保留部分成功结果并逐项报告，不承诺原子提交、自动回滚，也不承诺这些文件可通过 v1.0 的单 APK 安装入口直接装回。
- Logcat 的 `debug` 和 `info` 采用最低严重度阈值；Warning 没有独立按钮但包含在 `all/debug/info` 中，Fatal 没有独立按钮但包含在 `all/debug/info/error` 中。
- Logcat 文本和级别过滤只影响屏幕显示；下载始终保存操作时本次完整采集窗口的快照。
- Logcat 离页或进入后台时停止采集但在原 Session 有效期间保留静态有界快照；返回后可查看或下载，重新开始会清空旧窗口，断开或 Session 切换时清除旧快照。
- 配对码模式与本机配对的端口扫描均采用 30 秒单次窗口；超时后停止并等待用户明确重试，不自动续扫。
- 配对码输入只接受六位数字；满足格式后启用明确的“配对”按钮，输入本身和输入法完成动作均不自动提交。
- Shell 在页面可见期间采用单一持续交互式终端子流；普通字符先在主控端组成完整命令，提交时统一发送，高风险命令发送前确认。提交前特殊键只作用于本地编辑与历史；提交后远端程序运行期间 Esc、Tab 和方向键实时发送，Ctrl/Alt 采用高亮的一次性修饰状态且只作用于下一输入。离开终端页或应用进入后台时关闭子流并清除待提交命令、实时输入阶段与修饰状态，但在同一 Session 内仅于内存保留可见记录和命令历史；返回时建立新子流并显示会话分隔。断开或 Session 切换时清空全部终端上下文，不主动断开仍有效的主 ADB Session。
- 文件上传/下载、APK 提取/安装，以及 Logcat、截屏和既有录屏向主控端保存/导出文件，均从实际传输或写入开始成为阻止切页的长任务；文件选择器浏览与取消阶段不锁页。任务运行期间停留在所属页面，任务终态后恢复导航，应用进入后台时取消。复制文本、仅查看结果、持续交互式 Shell 和 Logcat 采集不锁页；Shell 与 Logcat 采集在离页时停止。
- 长任务期间系统返回采用确认式取消：默认继续并留在当前页，只有明确选择取消任务并离开且取消与清理完成后才返回。
- 普通状态下任意主页面的系统返回直接退出应用，不参与六页导航；当前浮层、确认框或长任务返回确认优先消费返回事件。
- 同一 Session 内保留文件、应用和进程页的路径或查询、滚动位置与最近快照；返回时先恢复，断开或 Session 切换时清空。Shell 和 Logcat 仍按各自更严格的生命周期规则处理。
- 性能指标使用固定大数据夹具进行自动化验证，并在既有三台被控端设备上补充真实滚动、过滤、刷新和切页体验证据。
- 用户可见版本字符串按明确要求为 `v1.0`；内部递增构建编号在 Plan 阶段依据当前构建配置确定，但必须与用户可见版本对应且不回退。

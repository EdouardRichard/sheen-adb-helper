# Feature Specification: v0.1 菜单与连接页 UI

**Feature Branch**: `006-menu-connection-ui`

**Created**: 2026-07-24

**Status**: Draft

**Input**: User description: "进行 0.1 版本需求分析：后续版本将使用新的 UI，本版本着重于顶部栏、底部栏、菜单栏以及连接页未连接/已连接状态；优先分析现有功能适配度，缺少功能再补齐；文件、应用、进程、Shell、日志页面不在本版本 UI 适配范围。"

## Current Capability Fit

The existing product already provides the core connection capabilities required by this feature:

- Manual IP-and-port connection and explicit disconnect.
- User-initiated local-network wireless-debugging discovery with a bounded 10-second window.
- Selection of discovered pairing or connection services.
- QR pairing, six-digit pairing-code pairing, and local-device pairing with bounded lifecycle handling.
- Device profiles stored locally and a connected-device overview with model, memory, storage, battery, charging, temperature, and uptime data.

The v0.1 gaps to close are the new navigation shell, moving device history into the menu, pull-to-refresh discovery, consistent connection-page state transitions, a local language preference, the About entry, and connected-page quick actions. Discovery, pairing, Session ownership, cancellation, timeouts, and structured errors remain existing capabilities and must not be weakened. Screenshot, screen recording, and reboot are newly authorized in this version under [ADR 0008](../../docs/adr/0008-connected-page-quick-actions.md). In all three quick actions, the target is the controlled device: the controller initiates the request, receives or exports the controlled device's screen content, and does not capture or reboot the controller itself.

## Clarifications

### Session 2026-07-24

- Q: 录屏时长与大小上限采用哪一组？ → A: 5 分钟或 256 MiB 任一条件先到即停止。
- Q: 截屏/录屏的保存位置交互采用哪种方式？ → A: 先写入应用临时文件，完成后再选择导出位置。
- Q: 截屏、录屏和重启是否允许并行？ → A: 三项快捷操作全局互斥，同一时间只运行一个。
- Q: 重启后的连接恢复采用哪种方式？ → A: 不自动重连，由用户手动重新连接。
- Q: 录屏是否包含音频？ → A: 仅录制设备画面，不包含设备音频或主控端麦克风。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 通过连接页建立或恢复连接 (Priority: P1)

用户打开应用后，在“连接”页看到当前是否已连接。未连接时，用户可以输入 `IP:端口`、点击连接图标、从局域网发现结果选择设备，或使用二维码、配对码、本机配对入口；连接成功后页面切换为已连接状态。已连接时，用户可以从顶部的断开图标结束当前 Session，页面回到未连接状态。

**Why this priority**: 连接页是所有被控端能力的入口，也是新 UI 的核心垂直切片。

**Independent Test**: 在没有活动 Session 的情况下分别验证手动连接、发现设备点击、二维码入口、配对码入口和本机配对入口；再验证成功连接、断开、取消、超时、拒绝和 Session 切换，不依赖文件、应用、进程、Shell 或日志页面。

**Acceptance Scenarios**:

1. **Given** 当前没有活动 Session，**When** 用户打开连接页，**Then** 顶部栏显示菜单按钮、`请输入 IP:端口连接` 输入框和连接图标，底部“连接”项处于选中状态。
2. **Given** 输入为空、格式非法或端口不在有效范围，**When** 用户点击连接图标，**Then** 不发起连接，并在输入附近给出可操作的错误提示。
3. **Given** 输入为有效端点且当前没有活动 Session，**When** 用户点击连接图标，**Then** 页面显示连接中状态；成功时切换到已连接页面，失败、取消和超时显示对应结果，不把请求已发送当作成功。
4. **Given** 局域网发现结果中存在可选择的设备，**When** 用户点击设备卡片，**Then** 系统使用该发现目标进入既有连接流程；没有活动 Session 时直接尝试连接，已有 Session 时先保留既有的替换确认和安全校验。
5. **Given** 当前已连接，**When** 用户点击顶部断开图标，**Then** 页面显示断开中状态，Session 关闭后回到未连接页面，且旧设备数据不再显示为当前设备。

### User Story 2 - 在未连接页面发现并完成配对 (Priority: P1)

用户可以在未连接页面下拉重新触发一次局域网扫描，也可以通过二维码连接、配对码配对或本机配对完成无线调试准备。所有流程都显示加载、空结果、失败、取消、超时和设备断开状态，并沿用现有敏感信息保护规则。

**Why this priority**: 无线调试设备可能不会出现在手动端点输入中，发现与配对是连接页的主要替代路径。

**Independent Test**: 使用可发现设备、不可发现设备、过期服务和本机无线调试设置分别验证扫描、刷新、二维码、配对码和本机配对；确认每次操作均有边界且不会留下旧 Session 结果。

**Acceptance Scenarios**:

1. **Given** 未连接页面处于可见状态，**When** 页面首次进入或用户下拉刷新，**Then** 系统开始一次最长 10 秒的局域网发现，显示扫描状态；扫描不枚举子网、不探测未公布端口，也不创建并行扫描。
2. **Given** 扫描返回设备，**When** 设备卡片展示，**Then** 第一行优先显示可靠设备名，第二行按“协议 · IP · 端口”显示端点；没有可靠名称时省略名称行。
3. **Given** 扫描超时、网络不可用、权限/能力不可用或结果为空，**When** 扫描结束，**Then** 页面显示明确原因和重新扫描入口，不伪造设备或连接成功。
4. **Given** 用户点击“扫描二维码连接”，**When** 二维码准备完成，**Then** 页面弹出仅在内存中有效的二维码并显示等待被控端扫描、取消、超时和失败状态；被控端扫描并完成配对后，系统尝试连接同一已验证的连接服务，无法自动解析时明确提示用户从列表选择连接服务。
5. **Given** 用户点击“配对码配对”，**When** 可用配对服务被发现，**Then** 页面要求输入六位数字配对码，复用现有校验、超时、取消、敏感输入清理和结果分类。
6. **Given** 用户点击“本机配对”，**When** 本机配对窗口开始，**Then** 页面立即显示扫描状态和停止操作；切换到系统无线调试设置后仍只在既定短时窗口内继续，并在成功、取消、端口失效或超时后清理临时状态。

### User Story 3 - 查看已连接设备状态并执行快捷操作 (Priority: P1)

用户连接成功后，连接页显示设备名称、端点和连接状态，并以紧凑卡片展示现有概览数据。用户还可以针对当前被控端执行截屏、录屏和重启；截屏/录屏获取被控端画面并交付到主控端，重启作用于被控端。这些操作必须先经过必要的文件选择或风险确认，并显示进行中、完成、取消、失败、超时或结果未知状态。数据暂时不可用时显示“设备未提供”或“未知”，不得用默认值伪装设备状态。

**Why this priority**: 用户需要在连接后立即确认连接到了哪台设备，并完成最常用的即时控制动作，而不必先进入其他页面。

**Independent Test**: 用可返回完整概览、部分字段缺失、连接中断和 Session 切换的设备验证已连接卡片、动态刷新、断开回退和旧数据清除；再分别验证截屏保存、录屏开始/停止/上限和重启风险确认。

**Acceptance Scenarios**:

1. **Given** Session 已连接且设备概览可读取，**When** 连接页显示，**Then** 顶部栏显示菜单按钮、实际端点和断开图标；主体显示设备名、绿色在线状态和已有的内存、存储、电池、充电、温度、运行时间等概览字段。
2. **Given** 某一概览字段不可读取或设备未提供，**When** 卡片显示，**Then** 该字段显示明确的不可用状态，不隐藏整张卡片、不填入零值或猜测值。
3. **Given** 连接页处于前台，**When** 动态状态刷新成功，**Then** 仅更新当前 Session 的动态字段；刷新失败显示当前操作错误，不清除仍有效的设备身份。
4. **Given** Session 断开、切换或结果过期，**When** 页面收到状态变化，**Then** 清除旧设备的名称、端点和概览数据，并回到未连接状态。
5. **Given** 当前 Session 支持截屏且用户点击“截屏”，**When** 系统完成一次被控端画面捕获并显示导出选择，**Then** 用户可将临时图片写入主控端明确选择的位置；用户取消导出时清理临时图片且不显示保存成功。
6. **Given** 当前 Session 支持录屏且用户点击“录屏”，**When** 被控端画面录制开始并写入有界临时文件，**Then** 页面显示录制中、已用时长、停止操作和当前文件状态；用户停止后进入导出选择，导出成功才视为生成可交付的视频文件。
7. **Given** 录屏达到 5 分钟或 256 MiB 任一上限，**When** 系统自动停止，**Then** 不创建第二段录制，并明确显示触发的上限和最终文件状态。
8. **Given** 当前 Session 支持重启，**When** 用户点击“重启”，**Then** 系统先显示被控端设备、未保存数据丢失、连接中断和结果未知风险；只有用户明确确认后才向被控端发送请求。
9. **Given** 重启请求已确认且设备随后断开，**When** 系统无法观察设备重新上线，**Then** 显示“请求已发送/结果未知”类中性结果，不把连接断开本身宣称为重启成功，也不自动发起重连。
10. **Given** 任一快捷操作遇到取消、超时、设备断开、Session 切换或能力不支持，**When** 操作结束，**Then** 停止相关任务、清理临时资源，并且不得向新 Session 交付旧文件或旧状态。

### User Story 4 - 使用顶部栏、底部栏和菜单栏导航 (Priority: P1)

用户可以通过统一的顶部栏打开菜单，通过底部栏切换主要页面，并在不改变既有页面业务逻辑的前提下从任何页面返回连接页。

**Why this priority**: 新 UI 的价值在于形成稳定的应用框架；页面内容可以在后续版本逐步替换，而导航行为必须先稳定。

**Independent Test**: 在连接和未连接两种状态下验证顶部栏、底部栏、菜单打开/关闭、选中态、返回行为、禁用项和大屏等价导航。

**Acceptance Scenarios**:

1. **Given** 任意页面处于前台，**When** 用户点击顶部左侧菜单按钮，**Then** 打开覆盖当前内容的菜单栏；点击关闭按钮、遮罩或返回键可关闭菜单且不改变当前 Session。
2. **Given** 移动宽度布局，**When** 用户查看底部栏，**Then** 依次提供“连接、文件、应用、进程、终端、日志”六个入口，当前页面有清晰选中态，视觉尺寸遵循设计稿且实际可点击区域符合当前 Android 可访问性基线。
3. **Given** 未连接且用户点击需要 Session 的底部入口，**When** 导航请求发生，**Then** 页面保持在连接页并给出“请先连接设备”提示；入口不伪装为可用，也不创建空 Session。
4. **Given** 大屏布局，**When** 用户查看导航，**Then** 提供与底部栏等价的持久导航，不要求用户通过横向滚动寻找入口；页面内容仍保持连接状态和 Session 规则一致。
5. **Given** 用户从底部栏切换到文件、应用、进程、终端或日志页面，**When** 页面打开，**Then** 使用现有功能和安全边界；本版本不重做这些页面的视觉内容。

### User Story 5 - 从菜单管理历史设备、设置和关于信息 (Priority: P2)

用户点击菜单后可以查看历史连接设备、进入设置并查看关于信息。历史设备从原首页迁入菜单，当前在线设备有在线标记，离线设备保留本地档案信息。

**Why this priority**: 菜单承接历史设备和系统级入口后，连接页可以专注于当前连接与发现，不再重复展示历史档案。

**Independent Test**: 使用至少一个在线档案、一个离线档案和空档案验证菜单展示、重新连接、编辑/删除保留、关于弹窗和设置入口。

**Acceptance Scenarios**:

1. **Given** 菜单栏打开，**When** 用户查看“历史连接设备”，**Then** 看到按最近连接时间排序的设备名称和端点；当前 Session 对应条目显示在线标记，其他条目显示离线状态。
2. **Given** 用户点击一个历史设备条目，**When** 该条目可重新连接，**Then** 使用现有设备档案发起连接；已有 Session 时先显示既有替换确认，不自动丢弃当前设备。
3. **Given** 菜单中的历史列表为空，**When** 用户查看该区域，**Then** 显示空状态和返回连接页手动连接/发现的提示，不创建示例设备。
4. **Given** 用户需要修改或删除设备档案，**When** 从历史条目触发已有操作，**Then** 保留既有名称编辑、删除确认、身份引用清理和本地持久化语义。
5. **Given** 用户点击“关于”，**When** 关于内容显示，**Then** 弹出固定文本：“制作不易，如果这个项目对你有帮助，欢迎到 GitHub 点个 Star，感谢支持。”并显示可点击链接 `https://github.com/EdouardRichard/sheen-adb-helper`；打开链接是用户主动操作，不在应用内自动联网。
6. **Given** 用户点击“设置”，**When** 设置页打开，**Then** 显示语言选项和现有设置/隐私入口；返回菜单后菜单状态和当前 Session 保持不变。

### User Story 6 - 在设置中切换中英文 (Priority: P2)

用户可以在设置页选择简体中文或 English。选择结果保存在本机，下次启动仍使用上次选择；切换后菜单、顶部栏、底部栏、连接页、错误状态和关于文本立即使用对应语言。

**Why this priority**: 菜单与连接页是新 UI 的长期基础，语言偏好必须在框架落地时确定，避免后续页面各自实现不同的语言状态。

**Independent Test**: 分别选择中文和 English，重启应用并验证所有 v0.1 新增或改版文案、按钮、空状态、错误状态和关于文本；确认选择不会触发网络请求或改变设备档案。

**Acceptance Scenarios**:

1. **Given** 首次使用且没有语言偏好，**When** 用户打开应用，**Then** 使用简体中文作为默认语言。
2. **Given** 用户在设置中选择 English，**When** 选择完成，**Then** v0.1 菜单、连接页和导航文案立即切换为 English，并显示当前选中项。
3. **Given** 用户重启应用，**When** 读取本地偏好，**Then** 恢复上次选择的语言；读取失败时安全回退到简体中文。
4. **Given** 用户切换语言，**When** 连接或配对流程正在进行，**Then** 不取消、不重启、不改变该流程，只更新可见文案。
5. **Given** 文件、应用、进程、Shell 或日志页面仍使用旧 UI，**When** 用户切换语言，**Then** 不改变这些页面既有业务逻辑；未纳入 v0.1 新 UI 的文案可以继续沿用现状，后续页面改版时再完整本地化。

### Edge Cases

- 用户连续点击连接/断开图标、底部栏或历史条目时，不得并行创建多个连接操作；当前操作必须显示进行中并可取消。
- 用户在扫描即将结束时下拉刷新，旧扫描结果不得覆盖新扫描结果；每次刷新最多产生一个 10 秒窗口。
- 发现服务在点击后过期、端口变化、配对服务与连接服务无法可靠关联或设备名称不可验证时，必须显示可操作的过期/未知状态，不把服务名、主机名或地址猜作设备名。
- 二维码、六位配对码和本机配对窗口结束、取消、Session 切换或连接成功后，敏感值和临时端点不得保留在页面、菜单、日志或持久化档案中。
- 用户打开系统无线调试设置后返回应用，若通知权限被拒绝、设备锁定、通知被关闭或本机配对服务不可用，应用内仍提供等价状态和停止/输入入口，不把通知限制误报为配对失败。
- 用户在已连接状态打开菜单并选择另一个历史设备时，必须先完成既有的当前 Session 替换确认；取消后当前设备页面不变。
- 连接成功后马上断开、应用退到后台、屏幕旋转或进程重建时，旧结果不得更新新 Session；连接页应恢复到与实际 Session 一致的状态。
- 设备名称为空、过长、包含控制字符或无法与当前已验证身份关联时，历史和扫描条目降级为无名称或明确的未知名称，不展示不安全文本。
- 设备概览部分字段缺失、刷新超时或设备拒绝读取时，只标记相应字段未知并保留设备身份；不得用 0、上一次设备的数据或其他设备的数据替代。
- 用户取消被控端截屏或录屏的导出选择、目标位置不可写、输出为空、格式无法识别或空间不足时，不得显示保存成功，也不得留下被误认为完整结果的损坏文件或未清理临时文件。
- 录屏接近 5 分钟或 256 MiB 边界时，界面必须仍可停止；任一上限先到即停止，不得压缩、拆分、自动续录或在后台继续录制。
- 截屏、录屏和重启同时被点击时，只允许当前 Session 的一个快捷操作占用对应资源；重复点击必须被忽略、禁用或返回明确的进行中状态。
- 重启确认被取消、返回或关闭时，不得发送请求；设备拒绝、命令超时、连接中断和重新上线失败必须分别显示可区分的非成功/结果未知状态。
- 重启后设备端点、网络或启动时间发生变化时，应用不得自动重连或把旧 Session 恢复为当前 Session；用户必须通过连接页或历史设备入口主动重新连接。
- 设备档案不存在、被删除或本地数据清除后，菜单显示空状态；不得生成示例历史设备或恢复旧身份。
- 语言偏好写入失败、未知语言值或应用升级后版本不兼容时，使用简体中文并保持连接、配对和历史数据不变。
- 任何页面通过底部栏跳转时都必须遵守现有单一活跃 Session、取消、超时、结构化错误和资源清理规则。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供统一的顶部栏、底部栏和菜单栏，且在连接与未连接状态下都可用。
- **FR-002**: 顶部栏 MUST 在未连接状态显示菜单按钮、`请输入 IP:端口连接` 输入区域和连接图标；输入错误 MUST 在不发起连接的情况下给出可操作提示。
- **FR-003**: 顶部栏 MUST 在连接中、断开中、配对中、等待授权、错误和已连接状态显示对应的状态表达，不把中间状态显示为成功或空闲。
- **FR-004**: 已连接状态的顶部栏 MUST 显示当前已验证端点和断开图标；断开完成后 MUST 回到未连接页并清除旧 Session 的连接页数据。
- **FR-005**: 底部栏 MUST 按“连接、文件、应用、进程、终端、日志”顺序提供六个入口，当前入口 MUST 有可感知的选中态；设计稿中的 44px 视觉尺寸 MUST 在应用界面中保持等价比例，实际可点击区域 MUST 不小于现有 Android 可访问性基线。
- **FR-006**: 未连接时，文件、应用、进程、终端和日志入口 MUST 保留可见但明确不可用，并提示用户先连接设备；不得绕过现有连接门槛。
- **FR-007**: 大屏布局 MUST 提供与底部栏等价的持久导航，且不得改变页面业务逻辑或 Session 归属。
- **FR-008**: 菜单栏 MUST 支持打开、关闭、遮罩点击和返回键关闭，并 MUST 在关闭后保留当前页面、语言和 Session 状态。
- **FR-009**: 菜单栏 MUST 从设备列表/首页迁移历史连接设备信息，按最近连接时间排序并显示名称、端点和在线/离线状态。
- **FR-010**: 历史设备条目 MUST 能触发现有重新连接流程；已有 Session 时 MUST 保留既有替换确认、取消和资源清理。
- **FR-011**: 既有历史设备名称编辑、删除确认、身份引用清理和本地持久化语义 MUST 保持可用，不得因迁移菜单而丢失。
- **FR-012**: 菜单 MUST 提供“设置”和“关于”入口；关于内容 MUST 包含固定支持文案和 `https://github.com/EdouardRichard/sheen-adb-helper` 链接。
- **FR-013**: 关于链接 MUST 只在用户主动点击后打开外部目标，应用 MUST NOT 自动联网、上传或请求账号。
- **FR-014**: 设置 MUST 提供简体中文与 English 两个互斥语言选项，默认简体中文，选择结果 MUST 在本机持久保存。
- **FR-015**: 语言切换 MUST 立即更新 v0.1 菜单、顶部栏、底部栏、连接页、状态、错误、空状态和关于文本，且不得取消或重启进行中的连接/配对流程。
- **FR-016**: 连接页 MUST 提供手动端点连接、局域网发现、二维码入口、六位配对码入口和本机配对入口，并保持现有能力限制。
- **FR-017**: 手动端点连接 MUST 绑定当前唯一活跃 Session，支持取消、有限超时、结构化错误和确定性资源清理。
- **FR-018**: 局域网发现 MUST 在首次进入连接页和用户下拉刷新时开始一次最长 10 秒的前台扫描；扫描 MUST 不枚举子网、不探测未公布端口、不并行运行。
- **FR-019**: 扫描结果 MUST 支持点击后进入现有连接流程；无活动 Session 时直接尝试连接，有活动 Session 时先显示既有替换确认。
- **FR-020**: 扫描条目 MUST 按“可选可靠设备名换行 + 协议 · IP · 端口”展示；无可靠名称时 MUST 省略名称行，不得猜测或截断名称。
- **FR-021**: 扫描 MUST 区分内容、空、扫描中、取消、超时、网络/能力不可用、解析失败和 Session 变化状态，并提供重试或手动输入入口。
- **FR-022**: 二维码入口 MUST 在内存中生成临时二维码，显示等待扫描、成功、取消、超时和失败状态；成功配对后 MUST 尝试连接同一已验证的连接服务，无法自动关联时 MUST 明确提示用户选择连接服务。
- **FR-023**: 六位配对码入口 MUST 复用现有六位数字校验、配对服务发现、超时、取消、错误分类和敏感输入清理。
- **FR-024**: 本机配对入口 MUST 复用现有有界本机扫描、通知/应用内降级、停止操作、解锁限制和临时状态清理规则。
- **FR-025**: 连接成功页 MUST 显示设备名称、当前端点、已连接状态和已有概览字段，包括内存、存储、电池、充电、温度和运行时间（设备提供时）。
- **FR-026**: 连接成功页对不可读取字段 MUST 显示明确未知/不可用状态，不得以零值、缓存的其他 Session 数据或猜测值代替。
- **FR-027**: 连接页动态刷新 MUST 只更新当前 Session 的动态字段；旧 Session、已取消、超时或断开结果 MUST NOT 更新新 Session。
- **FR-028**: 已连接页面 MUST 提供针对当前被控端的“截屏”“录屏”“重启”三个快捷操作入口；设备能力不可用时入口 MUST 明确显示不可用，不得发送未支持的请求。
- **FR-029**: 截屏 MUST 只捕获当前被控端在已验证 Session 下的一张画面并先写入有界应用临时文件；捕获完成后 MUST 要求用户通过系统文件选择器选择主控端导出位置，取消导出、捕获失败、超时或设备断开 MUST NOT 生成成功交付文件。
- **FR-030**: 截屏导出 MUST 只在用户选择位置中生成可读取图片；操作 MUST 支持有限超时、取消、结构化错误和确定性临时资源清理。
- **FR-031**: 录屏开始前不要求选择导出位置；录制 MUST 只采集被控端画面，先写入有界应用临时文件，并在录制期间显示进行中、已用时长、停止操作和当前临时文件大小或可用进度；停止后 MUST 要求用户选择主控端导出位置。
- **FR-032**: 录屏 MUST 只包含设备画面，不采集设备音频或主控端麦克风；录屏 MUST 在用户停止、达到 5 分钟或达到 256 MiB 任一条件时停止；任一上限先到即结束，MUST NOT 自动拆分、压缩续录、创建第二段或转入后台继续录制。
- **FR-033**: 录屏停止后 MUST 先验证临时文件，再进入导出选择；只有导出文件可读取且与当前 Session 绑定时显示交付成功；用户取消导出、导出失败、超时、断开、空间不足、空输出或格式无效 MUST 显示明确非成功结果并清理临时文件。
- **FR-034**: 重启入口 MUST 在发送前显示被控端目标设备、连接中断、未保存数据丢失和结果未知风险；只有用户明确确认后才能继续，取消或返回 MUST NOT 向被控端发送请求。
- **FR-035**: 被控端重启结果 MUST 区分已接受、设备拒绝/不支持、取消、超时、设备断开和结果未知；请求发送后连接断开本身 MUST NOT 被解释为重启成功，且系统 MUST NOT 自动重连。
- **FR-036**: 截屏、录屏和重启 MUST 绑定发起时的唯一活跃 Session，三项快捷操作 MUST 全局互斥，同一时间只允许一个快捷操作运行；每项操作 MUST 支持取消、有限超时、结构化错误、能力检测和确定性资源清理，旧 Session 的结果 MUST NOT 更新新 Session。
- **FR-037**: 快捷操作的原始 ADB 命令、二进制流、临时远端路径和异常适配 MUST 只位于 `:core:adb`；Feature/UI 只能消费项目自有状态和结果。
- **FR-038**: 快捷操作的临时文件 MUST 仅保存在应用私有临时位置并在成功导出、取消、失败、超时、断开或下次启动时幂等清理；最终交付 MUST 只写入用户明确选择的 SAF 位置，不得新增全盘存储、媒体库、相机或其他 Manifest 权限。
- **FR-039**: 文件、应用、进程、Shell 和日志页面在本版本 MUST 保持既有功能逻辑和安全边界，不得因新导航壳或快捷操作新增未授权能力或改变既有操作语义。
- **FR-040**: 所有 v0.1 操作 MUST 保持纯本地运行；不得新增账号、后端、广告、统计/遥测、支付、Root、无障碍自动化或业务云请求。
- **FR-041**: 连接、发现、配对、历史、语言偏好和快捷操作相关数据 MUST 遵守现有敏感数据和本地持久化边界；二维码、配对码、真实端点、原始 Shell/Logcat 内容、被控端截图和录屏内容 MUST NOT 写入本功能新增的历史或日志。
- **FR-042**: 本版本 MUST 保持现有单一活跃 ADB Session、Session ID 归属、取消、有限超时、结构化错误和资源关闭规则。
- **FR-043**: 顶部栏、底部栏、菜单栏和连接页 MUST 以 `D:\androidPorject\stitch_adb\technical_terminal_systems\DESIGN.md` 及本版本三个目标页面的 `code.html`/`screen.png` 为 UI 基准；应用界面 MUST 优先还原 `code.html` 表达的页面结构、组件层级、尺寸和状态，并使用 `screen.png` 做视觉核对。
- **FR-044**: UI 转换 MUST 保持 `DESIGN.md` 的 dark-first 色彩语义、4px 基线节奏、表面层级、圆角和 UI/技术数据双字体角色；当精确字体资产未获依赖/许可证批准时 MUST 使用本地 Sans Serif/Monospace 回退并记录偏差，不得运行时下载字体。
- **FR-045**: `code.html` 中引用的远程字体、样式、图标和其他 Web 资源只作为设计表达；产品运行时 MUST 使用本地资源，MUST NOT 因 UI 还原引入 CDN 或业务网络请求。
- **FR-046**: 本版本构建标识 MUST 更新为 `versionName 0.1.0`、`versionCode 3`；菜单页脚 MUST 显示该实际构建版本并保持中英文可读，MUST NOT 复制设计稿中的占位版本号。

### Scope Boundaries

- 本版本只适配顶部栏、底部栏、菜单栏和连接页未连接/已连接状态；连接页以外的文件、应用、进程、Shell、日志页面不进行新视觉设计。
- 历史连接设备从连接页迁移到菜单，但设备档案的重命名、删除、身份引用清理和重新连接能力不移除。
- 局域网发现仍使用现有的系统公布服务发现和最长 10 秒窗口；本版本只增加下拉刷新和新的展示/点击入口，不扩大网络探测范围。
- 二维码、配对码和本机配对沿用现有生命周期与安全规则；二维码成功后增加同一已验证连接服务的连接尝试，但无法关联时不得伪装为已连接。
- 已连接页面复用现有概览数据；处理器利用率仍需设备提供可靠指标。截屏、录屏和重启按 ADR 0008 实现为用户主动、前台、有界的快捷操作，不扩展到后台自动采集或批量控制。
- 截屏和录屏先写入应用私有临时文件，再通过用户明确选择的 SAF 位置交付；临时文件不得成为未选择的持久输出，且必须在终态幂等清理。本版本不申请主控端全盘存储、媒体库或相机权限。录屏默认最长 5 分钟或 256 MiB，以先到者为准。
- 重启属于高风险单设备操作，每次必须单独确认；设备因重启而断开时，除非用户主动重新连接并获得可验证证据，否则只报告请求已发送或结果未知，应用不自动重连。
- 不新增 Manifest 权限、第三方依赖、后台常驻任务、云端服务、Root、无障碍或设备管理能力。
- 不重写既有 Feature 的业务逻辑；必要新增只限于导航状态、连接页呈现、历史入口迁移、下拉刷新、关于文本、语言偏好以及 ADR 0008 规定的三项快捷操作。

### Key Entities

- **导航状态**: 当前底部栏入口、菜单是否打开、页面可用性和当前语言。
- **连接页状态**: 未连接、连接中、等待授权、已连接、断开中、配对中和错误状态，以及当前 Session 归属。
- **发现设备条目**: 可选可靠名称、协议、IP、端口、发现状态、配对/连接角色和可用操作。
- **设备历史条目**: 本地设备档案的显示名、端点、最近连接时间、在线/离线状态和可用重新连接操作。
- **语言偏好**: 简体中文或 English 的本地选择及默认回退状态。
- **关于信息**: 固定支持文案、项目链接和可关闭的弹出内容。
- **概览字段**: 当前设备的名称、端点、连接状态、内存、存储、电池、充电、温度、运行时间及各字段可用状态。
- **截屏任务**: 当前 Session 对被控端的一次性画面捕获、临时文件、主控端用户选定的导出位置、状态、错误和清理结果。
- **录屏任务**: 当前 Session 对被控端的一次有界视频捕获、临时文件、开始/停止时间、已用时长、文件大小、上限触发原因、主控端导出位置和输出文件状态。
- **重启请求**: 用户确认后针对被控端发起的高风险重启操作、Session 归属和可观察结果分类。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在连接和未连接两种状态下，100% 的受测页面都能在一次操作内打开/关闭菜单，遮罩或返回键关闭成功率为 100%，且关闭不会丢失当前 Session。
- **SC-002**: 移动布局中，100% 的受测设备都显示六个底部栏入口，当前入口识别正确率为 100%，视觉尺寸与设计稿一致且每个入口的实际可点击区域符合当前 Android 可访问性基线。
- **SC-003**: 在现有三台被控端设备上，100% 的非法端点输入不会发起连接；有效端点连接在 10 秒内返回成功、失败、取消或超时中的明确结果，且不会出现“请求已发送即成功”的误报。
- **SC-004**: 每次下拉刷新都只产生一个最长 10 秒的扫描窗口；连续 20 次刷新中并行扫描数为 0，扫描结果过期后旧条目覆盖新条目的次数为 0。
- **SC-005**: 对具名、无名、IPv4、IPv6、端口变化和过期服务夹具，100% 的条目按“可选名称 + 协议 · IP · 端口”展示，猜测名称、截断名称和旧式缺失地址文案次数为 0。
- **SC-006**: 二维码、配对码和本机配对的取消、超时、端口失效和 Session 切换回归用例 100% 通过；敏感配对值进入持久记录的次数为 0。
- **SC-007**: 使用包含至少 3 个历史设备档案的数据集验证在线/离线状态，并另行验证空列表场景；菜单排序、状态标记、重新连接、编辑和删除结果正确率为 100%，连接页不再重复展示历史列表。
- **SC-008**: 关于入口 100% 显示指定文案和完整 GitHub 链接；应用自动联网、自动打开链接或上传数据的次数为 0。
- **SC-009**: 中英文切换后，100% 的 v0.1 新增/改版文案在 1 秒内更新；重启后语言偏好恢复率为 100%，异常偏好值均回退到简体中文。
- **SC-010**: 已连接页面在完整和部分缺失概览数据的设备上 100% 显示设备身份和可用状态；不可用字段被明确标记，伪造零值或跨 Session 数据的次数为 0。
- **SC-011**: 连接成功后断开或切换 Session 的回归用例 100% 清除旧端点、设备名和概览，不得让旧结果更新新 Session。
- **SC-012**: 文件、应用、进程、Shell 和日志既有回归用例全部通过；除导航入口和连接页壳变化外，用户可见业务退化次数为 0。
- **SC-013**: 本版本不新增 Manifest 权限、第三方依赖、后台常驻任务、账号、后端、广告、统计/遥测、支付、Root 或无障碍能力；审查记录与构建产物一致。
- **SC-014**: 对现有三台被控端逐台执行能力检测；每台报告支持截屏的设备执行 3 次捕获和导出，3 次均须在 10 秒内进入导出选择并生成可读取图片。低版本设备报告不支持时视为正确降级而非失败；所有取消、超时、断开和失败路径误报成功次数为 0。
- **SC-015**: 对每台报告支持录屏的被控端执行 3 次正常短时停止和导出，均须生成可读取的无音频单段视频；用户停止、5 分钟和 256 MiB 上限由自动化边界测试全部覆盖。低版本设备报告不支持时视为正确降级；自动第二段、后台续录、音频轨道或未清理临时文件次数为 0。
- **SC-016**: 100% 的重启尝试在发送前显示风险并要求单独确认；未确认发送次数为 0，连接断开但未取得重新上线证据时宣称“重启成功”或自动发起重连的次数为 0。
- **SC-017**: 在取消、超时、断开、Session 切换、能力不支持和临时文件清理验收中，快捷操作向新 Session 交付旧状态或旧文件的次数为 0。
- **SC-018**: 快捷操作的设备不支持、输出为空、空间不足、权限拒绝和格式无效均返回可区分的非成功结果；不新增 Manifest 权限、全盘存储访问或第三方媒体/录制 SDK。
- **SC-019**: 将主控端截图归一化到设计参考宽度 468px，并分别按未连接/已连接参考高度 1060px、菜单参考高度 1046px 核对；顶部/底部栏、抽屉宽度、主要卡片、操作入口、色彩层级、间距和圆角均有对应原生界面，系统栏差异和设备能力降级必须单独记录。
- **SC-020**: 构建产物和源码扫描中，设计稿引用的远程字体、样式、图标或其他设计资源网络请求次数为 0；菜单版本占位值进入产品 UI 的次数为 0。

## Assumptions

- `DESIGN.md` 的 44px 是视觉基准；实际触控区域保持现有 Android 可访问性基线。
- 当前验收资源为一名用户、三台被控端设备，其中一台系统版本低于 Android 10。主控端应用仍只运行在项目 `minSdk 30` 及以上设备；低版本设备只作为被控端参与连接、能力检测和降级验收。
- 移动布局使用设计稿中的六项底部栏；大屏使用等价的持久导航，不改变入口语义。
- “点击扫描设备后建立连接”在没有活动 Session 时不再要求额外的展示确认；已有活动 Session 仍遵守既有替换确认，避免误断开当前设备。
- 二维码配对成功后自动尝试连接同一已验证连接服务；若平台只返回配对成功而未提供可验证连接服务，页面显示“已配对，请选择连接服务”，不得声称已连接。
- 历史设备显示名、端点和连接时间沿用现有本地设备档案；菜单中的在线状态只表示当前 Session 与该档案端点/身份匹配，不代表设备持续在线。
- 默认语言为简体中文；English 只要求覆盖本版本新建或改版的菜单、连接页、导航、状态、错误、空状态和关于文本，未改版页面可暂时保留既有文案。
- 设计稿中的处理器占用仍按设备能力决定是否显示可用值；截屏、录屏和重启已由用户批准纳入本版本，并按 ADR 0008 的边界实现，不延伸为远程批量控制、后台录制或自动重启。
- 截屏默认使用当前设备画面的一次性捕获并先保留为临时文件；录屏默认先写入应用临时文件，停止后再选择导出位置，并在用户停止、5 分钟或 256 MiB 任一上限先到时结束。
- 录屏默认只包含被控端画面，不包含设备音频或主控端麦克风；主控端屏幕不作为录制来源，也不因此请求麦克风或其他音频采集权限。
- 重启结果通常会因设备主动断开而不可立即观察；除非用户手动重新连接且状态可验证，应用只显示请求已发送或结果未知，不自动重连。
- 现有权限矩阵、依赖白名单、单活跃 Session、短时本机配对窗口和敏感数据规则继续有效；若实现发现必须扩大其中任一边界，应先暂停并新增 ADR。

# README 主要功能演示设计

## 目标

以 Android 16 模拟器作为主控端、Android 12 模拟器作为被控端，搭建隔离的 TAP 同网环境，通过 Sheen ADB 助手自身完成配对、认证与连接，采集真实、脱敏的主要功能截图，并重写根目录 `README.md`。

README 面向首次了解项目的用户。读者应能快速回答：

1. 这个 App 是什么；
2. 它可以做什么；
3. 如何开始使用；
4. 它如何保护隐私。

1. 产品名称与一句话定位；

3. 核心能力摘要；
4. 配对与连接；
5. 设备概览；
6. 文件管理；
7. 应用管理；

设置、构建和工程文档不占据首屏，统一放在 README 后部。

## 截图计划

截图存放在 `docs/images/readme/`，使用稳定、描述性的英文文件名。保留以下 7 张核心截图：

- 连接或配对入口；
- 已连接的设备概览；
- 文件管理；
- 应用管理；
- 进程管理；
- Shell 终端；
- Logcat；

只有当连接成功状态无法在前两张截图中清楚表达时，才增加第 8 张连接成功画面。

每张截图只配一句说明。截图必须来自本次实际运行，不使用设计稿或静态数据冒充运行结果。

## 环境与连接约束

环境遵循用户附件《多模拟器同一网络提示词》：

- 从当前机器读取 Android SDK、AVD、Java、TAP 和 Network Bridge 的真实配置，不猜测；
- 每台模拟器使用独立 console 端口和独立 TAP；
- Android 16 为主控端，Android 12 为被控端；
- 两台设备均需完成开机，Wi-Fi 实际连接并保持稳定；
- TAP 地址位于同一隔离测试子网，双向可达，目标路由经过 TAP；
- 所需 mDNS、TLS 或 ADB 服务必须由被控端真实发布；
- 配对、认证和业务连接必须由 Sheen ADB 助手完成；
- host ADB 只用于启动、安装、准备数据、UI 自动化、截图和只读状态确认，且每条命令显式指定 serial；
- 不使用 host `adb connect` 或 `adb pair` 替代产品能力。

任一硬性门槛失败时，先修复或如实记录环境阻塞，不制造成功画面。

## 隐私与证据

README、截图和报告不得包含：

- 真实 IP、动态端口；
- 配对码或二维码内容；
- ADB 密钥、证书或签名材料；
- 真实包名上下文；
- Shell 原文；
- Logcat 原文；
- 其他可识别设备或用户的数据。

截图优先通过准备无敏感含义的演示数据和界面裁切规避敏感内容；必要时只对敏感区域做不可逆遮挡，不改变功能状态或伪造结果。

## README 文风

- 中文为主；
- 首屏简洁，优先说明用户价值；
- 使用短段落、短列表和明确标题；
- 不复制规格文档式长篇描述；
- 不宣传未在本次环境中成功演示的功能；

- 保留必要的构建、隐私、权限、许可证和工程文档入口。

只修改：

- `README.md`；
- `docs/images/readme/` 下的本次演示截图；

不修改应用逻辑、Manifest、权限矩阵、依赖、ADR 或当前 Spec Kit 规格。

## 验证

完成后执行：

1. 核对两台模拟器版本与角色；
2. 记录 TAP、Network Bridge、Wi-Fi、同子网、双向可达和路由的脱敏结论；
3. 确认产品自身完成配对、认证和连接；
4. 逐张核对截图与实际功能状态一致；
5. 扫描截图和 README，确认无敏感值；
6. 检查 README 中所有本地图片和文档链接存在；
7. 检查 Markdown 结构与渲染可读性；
8. 运行 `git diff --check`；
9. 将模拟器证据与未执行的真实设备验收明确分开。

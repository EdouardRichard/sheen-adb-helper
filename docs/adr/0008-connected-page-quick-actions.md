# ADR 0008：连接页快捷操作（截屏、录屏、重启）

- 状态：Accepted
- 日期：2026-07-24
- 决策者：项目负责人（已批准纳入 v0.1）
- 关联规格：[`specs/006-menu-connection-ui/spec.md`](../../specs/006-menu-connection-ui/spec.md)

## 背景

v0.1 连接页设计包含“截屏”“录屏”“重启”三个快捷操作。当前仓库已有单一活跃 ADB Session、结构化结果、取消/超时和资源清理边界，但尚未把这三项能力接入连接页，也未定义被控端捕获、主控端输出、录屏上限和重启结果语义。

这些操作涉及二进制媒体输出、长时流、设备主动断开和高风险控制。若直接由 UI 拼接 Shell、写入未选择的路径或把断开视为成功，会违反 ADB 边界、敏感数据、最小权限和结果未知原则。

## 决策

### 1. 统一入口与 Session 归属

- 已连接页显示三个快捷操作：截屏、录屏、重启。
- 三项快捷操作的目标均是当前被控端：截屏和录屏获取被控端屏幕，重启作用于被控端；主控端只发起请求、接收/导出结果，不捕获或重启主控端。
- 三项操作均只面向当前唯一活跃 Session；开始、进度、完成、取消、超时、断开和清理状态必须携带 Session ID。
- 截屏、录屏和重启全局互斥；任一快捷操作运行时，其他两个入口必须禁用或明确显示“操作进行中”，不得并行占用当前 Session。
- `:core:adb` 独占原始 ADB 命令、二进制流、设备能力检测、异常映射、超时、取消和远端资源清理；Feature/UI 只消费项目自有状态和结构化结果。
- `feature:overview` 内部 Use Case 通过项目自有端口协调 `:core:adb` 与 `:core:data` 的 artifact、捕获、导出和终态清理；两个 core 模块互不依赖，Feature 内部适配器不得向 ViewModel/UI 暴露协议字节流或平台类型。`:app` 只构造/注入 Use Case、负责导航，并把系统文件选择结果转换为项目自有导出目标后回传，不拥有快捷操作业务编排。
- 截屏、录屏和重启能力必须逐项探测，不得仅按被控端系统版本推断；低版本设备明确返回不支持属于正确降级。
- 设备不支持、策略拒绝、输出为空、格式无效、空间不足和结果未知必须作为明确的非成功分类，不得隐藏或伪装为成功。

### 2. 截屏

- 截屏是一次性、前台、用户主动的被控端当前画面捕获。
- 捕获先写入有界的应用私有临时文件；捕获完成后通过系统文件选择器由用户选择主控端导出文件。用户取消导出即清理临时文件，不创建未选择的持久输出。
- 捕获过程设置有限超时，输出必须通过有界的二进制流传递并在写入后验证为可读取图片。
- 失败、取消、超时、断开或 Session 变化时清理临时输出；不得把部分或空文件标记为成功。
- 不申请相机、媒体读取、全盘存储或其他新增 Manifest 权限；输出只进入用户明确选择的 SAF URI。

### 3. 录屏

- 录屏开始前不要求选择主控端输出位置；录制被控端画面并先写入有界的应用私有临时文件，停止后进入主控端导出选择；录制期间页面显示录制中、已用时长、停止操作和文件大小/进度。
- 录屏只包含设备画面，不采集设备音频或主控端麦克风；不申请麦克风、音频采集或其他新增权限。
- `:core:adb` 通过设备能力适配器启动当前设备支持的录屏流，并将其绑定到当前 Session。录屏先写入有界的应用私有临时文件；实现可使用有界的远端临时媒体工件再转入该临时文件，但远端路径必须是每次任务独有的不可预测临时值，且不得进入日志或用户历史。
- 录屏在用户停止、5 分钟或 256 MiB 任一条件先到时结束；达到边界后不得自动拆分、压缩续录、创建第二段或继续后台录制。
- 正常停止先验证临时文件并进入导出选择；只有导出文件可读取且与当前 Session 绑定时才报告交付成功。取消导出、导出失败、超时、断开、空间不足、空输出和格式无效时清理损坏临时文件并报告可区分的非成功结果。
- 录屏不使用 MediaProjection、第三方录制 SDK 或新增主控端权限；能力不足时保留不可用状态和手动排查提示。

### 4. 重启

- 重启是作用于被控端的高风险单设备操作，入口必须先显示被控端目标设备、未保存数据丢失、连接中断和结果未知风险。
- 只有用户明确确认后，`:core:adb` 才能向当前 Session 发送重启请求；取消、返回或关闭确认不得发送。
- 设备因重启主动断开时，默认结果为“请求已发送/结果未知”或“设备已断开”，不是“重启成功”。只有设备重新连接并取得可验证的新 Session/状态，才可显示后续已观察结果。
- 重启后不自动重连；用户通过连接页或历史设备入口主动发起新的连接，避免在端点、网络或设备启动状态变化时误连。
- 不使用 Root、Shizuku、设备管理员、无障碍自动化或其他绕过平台限制的方式；不自动重试、不批量重启、不在后台触发。

### 5. 生命周期与互斥

- 快捷操作支持取消、有限超时、结构化错误和确定性资源清理。
- 同一 Session 的录屏只能有一个活动任务；重复点击必须被忽略、禁用或返回进行中状态。
- 截屏、录屏和重启共享同一互斥门；任一操作运行时，其他快捷操作不得开始。
- 断开、Session 切换、页面离开或进程清理会停止本地任务，并尽力清理远端临时工件；旧结果不得更新新 Session。
- 快捷操作不写入脱敏诊断历史、不自动上传、不自动分享、不写入未选择的持久位置。

## 权限、依赖与数据影响

- 不新增 Manifest 权限。截图/录屏输出使用既有 Storage Access Framework；不申请全盘存储、媒体读取、相机或 MediaProjection。
- 不新增第三方依赖或媒体/录制 SDK。
- 截图、录屏文件可能包含设备、应用、进程和日志上下文；离开应用前必须由用户明确选择输出位置，并按用户选择交付。
- 原始截图/录屏二进制、远端临时路径和重启原始命令不得写入仓库、Logcat、诊断历史或设备档案。

## 影响

### 正面

- 连接页提供设计稿要求的即时设备操作，同时保持本地优先和最小权限。
- 媒体输出先进入有界应用临时文件，再通过用户选择的 SAF 位置交付，避免扩大主控端文件访问能力和留下未选择的持久输出。
- 重启的风险确认和结果未知语义避免把 ADB 请求发送误报为设备状态已验证。
- 快捷操作遵守既有 `:core:adb` 边界，可沿用 Session、取消、超时和清理测试。

### 代价与风险

- 需要在 `:core:adb` 增加二进制捕获、录屏生命周期和重启结果分类，并在 Feature/UI 增加对应状态和确认。
- 部分 ROM 可能不支持录屏格式、输出重定向或重启请求；必须展示能力不支持/策略拒绝而不是扩大权限。
- 录屏可能产生较大文件；5 分钟/256 MiB 上限和用户选择位置用于控制资源风险。
- 重启后连接断开是预期行为，真机验收必须区分请求已发送、结果未知与用户手动重新连接后可验证状态；自动重连次数必须为 0。

## 被拒绝方案

- 在 UI 或 Feature 中直接拼接 ADB Shell 命令：违反 ADB 边界和 Session 归属。
- 自动保存到应用私有目录并对用户宣称已保存：用户未明确选择持久位置，且不满足可审计交付。
- 使用 MediaProjection、第三方录制 SDK、全盘存储或媒体读取权限：扩大权限/依赖范围，当前目标不需要。
- 把设备断开直接视为重启成功：无法区分请求发送、设备拒绝、网络中断和未知结果。
- 自动重试、后台续录、自动拆分录屏或批量重启：扩大生命周期和控制范围，超出 v0.1。

## 验证与回滚

- 自动化覆盖：能力检测、截图输出验证、录屏停止/上限/取消、Session 切换、远端临时工件清理、重启确认和结果分类。
- 构建与 Manifest 审查必须确认无新增权限、无新增第三方媒体依赖，且输出只经过 SAF。
- 真机覆盖当前三台被控端（其中一台低于 Android 10）：三台均验证连接和逐项能力结果；每台报告支持的截图/录屏执行对应成功路径，低版本设备明确不支持时记录为正确降级。另覆盖录屏时间/大小上限、重启后主动断开与重新连接，以及低存储/用户取消文件选择。
- 若某 ROM 无法可靠完成截图、录屏或重启，回滚对应快捷操作的可执行入口并保留不可用原因；不得通过新增权限、Root、后台服务或绕过控制补救。
